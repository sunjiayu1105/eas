# 4.11 技术栈版本与使用规则

以下内容按照当前项目 `AGENTS.md` 项目级规则中规定的技术栈版本为准。

以下为项目统一技术栈版本。当前 ES 同步链路为 `MySQL → Canal Server（RocketMQ 模式）→ RocketMQ → 自定义 RocketMQ 消费与 ES 写入服务 → Elasticsearch`。已有业务 MQ 消费者仍属于停写和恢复的控制范围，两项独立校验通道不因引入同步 MQ 而合并职责。本文不另行指定 ShardingSphere-JDBC 版本；Canal Server 和 Adapter 按项目规则固定为 1.1.7，Adapter 不作为主链路写入组件。

- **Java**：8
- **Spring Boot**：2.7.18
- **rocketmq-spring-boot-starter**：2.3.0
- **org.apache.rocketmq:rocketmq-client**：5.2.0
- **Elasticsearch 服务端**：7.17.15
- **MySQL**：8.0.33
- **Canal Server**：Alibaba Canal Server 1.1.7（单机部署，不使用 ZooKeeper 高可用）
- **Canal Adapter**：Alibaba Canal Adapter 1.1.7（ES 7 Adapter）

## 已确认规则

- 上述版本是项目基线，不得用参考文章的 Canal 1.1.6、MQ 4.9.4 或 ES8 示例替换。
- Canal Server 部署方式与参考文章的单机方案一致：1 个 Server 进程承载 db0、db1，使用 file-instance.xml 本地位点模板，故障后人工核对并重启；不配置 ZooKeeper 或自动主备切换，实际落盘和恢复仍待验证。
- 5.2.0 仅指定 org.apache.rocketmq:rocketmq-client，不代表 Broker 版本，也不代表采用 rocketmq-client-java gRPC SDK。
- ES 7.17.15 指服务端版本；实际客户端类型、应用依赖树和运行兼容性仍须验证，不把候选示例记为已部署事实。

**兼容性判断边界**：已按官方资料核对 Canal 1.1.7 的 RocketMQ 模式候选配置与消息模型；RocketMQ Spring 2.3.0 传统客户端父 POM 指定 Java 8 和 client 5.2.0；Spring Boot 2.7.18 BOM 默认管理 ES 7.17.15。005～009 的配置和核心 API 已按这些版本修正，实际发行包、依赖覆盖、认证、连接、原生 RocketMQ 发布和端到端同步仍未验证；依据见 009。

**项目版本与候选版本分开**

正文、配置和代码示例均以上述版本为边界。Canal Server/Adapter 1.1.7 是当前项目版本边界，源码核对链接采用 `canal-1.1.7` 标签；实际安装包、ShardingSphere-JDBC、JDBC 驱动及其他未指定依赖仍须结合构建配置和联调环境核对。
