## 2 面试口述精炼版本

历史数据导入新库新表并通过数据库侧校验后，我们再上线 Canal 向 ES 的同步功能，同时启动新表与 ES 的数据校验。历史数据和后续新增、更新的数据会一起同步。

历史导入所需的月份索引在导入前单独准备。创建时将生命周期起点设为所属月份的下个月 1 日零点，按中国标准时间计算。历史索引可能已经达到迁移或删除期限，所以先绑定只有 hot 阶段的临时策略，不执行迁移或删除；创建成功且配置核对通过才算准备完成。详见 3.2。

确认历史范围已同步并校验通过后，继续观察增量同步和数据一致性。观察验收通过后，再切换正式策略。从上述起点满 366 天的索引具备冷数据层迁移资格，实际执行可以延后。

## 3 详细方案

### 3.1 同步期间绑定回放策略

```http
PUT /_ilm/policy/consume-replay
{
  "policy": {
    "phases": {
      "hot": { "actions": {} }
    }
  }
}
```

历史索引按所属月份计龄，创建时可能已经达到正式策略的年龄条件。回放策略只保留 hot 阶段且不配置迁移、只读或删除动作，用于在同步和验收完成前控制 ILM 的自动动作；数据同步仍正常进行。索引是否位于热数据层（hot data tier），需结合索引分配设置和分片状态检查，不能仅凭 hot 阶段判断。

[来源：索引生命周期](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/ilm-index-lifecycle.html)说明阶段与动作；[数据层](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/data-tiers.html)说明数据层角色和分配机制。

### 3.2 创建历史索引

历史导入所需月份索引在导入前单独准备，不能等待消费者首次写入时创建。创建时应用模板中的 Mapping、公共配置和读别名，显式绑定回放策略，并逐月设置所属月份下个月 1 日零点的毫秒时间戳。重复执行发现同名索引时须核对配置，创建成功且配置核对通过才算准备完成。重试、告警、后台手动启动和运维兜底见 [04 索引设计与创建](<030_ES改造_ES_索引设计、创建与写入.md>) 第 3.3 节。以下使用已确认的中国标准时间（UTC+08:00）；配置未执行：

```http
PUT /records-2024.01
{
  "settings": {
    "index.lifecycle.name": "consume-replay",
    "index.lifecycle.origination_date": 1706716800000
  }
}
```

`index.lifecycle.origination_date` 用于指定 **ILM 计算索引年龄的起始时间**。示例中，`records-2024.01` 的计龄起点为 2024-02-01 00:00:00+08:00，对应 `1706716800000`。实际值按所属月份的下个月 1 日零点及统一业务时区计算，不能直接复用示例值。[来源：ILM 设置](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/ilm-settings.html)

### 3.3 正式策略与切换

以下未执行示例只展示正式策略的冷热迁移部分。包含 `1830d` 删除阶段的策略见 [ES写入链路_ES_索引保留期与删除](<./032_ES改造_ES_生命周期管理_到期删除.md>)，两份示例应合并理解，不应依次提交覆盖同名策略。

```http
PUT /_ilm/policy/consume-normal
{
  "policy": {
    "phases": {
      "hot": { "actions": {} },
      "cold": {
        "min_age": "366d",
        "actions": { "migrate": { "enabled": true } }
      }
    }
  }
}
```

确认历史范围已同步并校验通过后，继续观察增量同步和数据一致性；不能因某次校验未发现差异就立即切换。观察期满足验收要求后，检查目标索引仍处于回放策略 hot 阶段且没有未完成动作，再执行策略切换。以下仅展示目标策略绑定设置，不能作为已经验证的完整切换流程；旧策略移除、缓存阶段定义和切换后状态须按官方切换流程核对：

```http
PUT /records-2024.01/_settings
{
  "index.lifecycle.name": "consume-normal"
}
```

已经进入 cold 或正在迁移的索引应先检查状态，不能把策略切换视为立即撤销动作。[来源：更新生命周期策略](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/update-lifecycle-policy.html)、[Migrate 动作](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/ilm-migrate.html)

### 3.4 核对阶段与实际迁移状态

按上述 UTC+08:00 示例，从 2024-02-01 零点起算 `366d`，到 2025-02-01 零点满足 cold 的年龄条件；实际进入 cold 还需完成验收并切换到正式策略。`366d` 是固定时长，不等同于任意日期的一整个自然年。历史索引切换正式策略时可能早已达到该期限，切换后无需重新等待 366 天；具体阶段推进取决于 ILM 调度和执行状态。

```http
GET /records-2024.01/_ilm/explain
```

检查实际策略、阶段、步骤和错误信息；迁移完成情况还需结合分片分配确认。本项目不使用 rollover，各阶段 `min_age` 相对于 `origination_date` 计算，不会在进入上一阶段后重新计时，删除阶段也使用同一起点。[来源：ILM 设置](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/ilm-settings.html)支持计龄规则；[Explain lifecycle API](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/ilm-explain-lifecycle.html)说明策略、阶段及步骤状态的查询。
