# 3.1.3 数据模型

以下内容按照当前项目 `AGENTS.md` 项目级规则中规定的技术栈版本为准。

**面试口述精炼版本**

**主键设计**

新表以 `consumeId` 为主键，由雪花 ID 拼接固定 2 位分片编号生成，按字符串保存。

**分片定位**

分片定位有两种入口，最终都得到同一个 `shardIndex`：

- **根据 `merchantNo` 定位**：凡是能够提供 `merchantNo` 的新增、更新和查询场景，都对 `merchantNo` 做哈希取模，得到 `shardIndex`。
- **根据 `consumeId` 定位**：读取主键末尾固定 2 位，直接得到 `shardIndex`，用于不额外提供 `merchantNo` 时的主键回查。

两种入口都按同一公式计算库表：

`shardIndex` 的取值范围是 `0～31`。按每库 16 张表计算逻辑库和逻辑表编号：

```text
库编号 = shardIndex / 16        // 整数除法，结果为 0 或 1
表编号 = shardIndex % 16        // 余数范围为 0～15
```

例如，`shardIndex = 7` 时定位到逻辑库 0、逻辑表 7；`shardIndex = 23` 时定位到逻辑库 1、逻辑表 7。逻辑编号还要经过项目统一的库表名称映射，才能得到实际数据库和物理表名；具体名称以生产配置为准。

主键末尾的分片编号由生成主键时使用的 `merchantNo` 路由结果写入，因此两种入口在规则一致时应定位到同一分片；生成、解析和路由映射仍需结合实际代码验证。

**历史迁移关联**

交易流水号 `serialNo` 全局唯一且不变。DBA 完成历史迁移后，先用 `serialNo` 对应新旧表中的同一笔记录，再按历史验收范围比较字段；旧表 `id` 与新表 `consumeId` 不直接比较。

**详细方案**

本节详细方案与“面试口述精炼版本”的主键设计、分片定位和历史迁移关联内容保持一致。
