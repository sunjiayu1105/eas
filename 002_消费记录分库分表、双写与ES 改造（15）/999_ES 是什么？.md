# 4.4 ES 是什么？

以下内容按照当前项目 `AGENTS.md` 项目级规则中规定的技术栈版本为准。

**定位：面向检索与分析的文档引擎**

Elasticsearch（ES）基于 Lucene，以 JSON 文档保存和检索数据。Mapping 定义字段类型及索引方式：`text` 通常先分词，`keyword` 按完整值匹配；数值和日期可使用 BKD 点值索引，排序、聚合通常读取 `doc_values`。原始 JSON 默认保存在 `_source`。

**分片：把数据与查询负载分散到节点**

索引分成多个主分片，每片可有副本。查询时，协调节点从每个目标分片的可用副本中选择一份执行，该份可以是主分片或副本分片，再汇总结果。副本能分担读取压力，不能减少一次跨所有分片查询需要涉及的逻辑分片数。

**副本：在故障时接替主分片**

同一主分片与其副本分配在不同节点。主分片故障后，可用副本可以被提升；这依赖副本正常、集群能够选主等条件，节点数量本身不能证明容灾已验证。

**项目边界：查询副本存在同步和刷新延迟**

ES 可通过聚合计算数量、总和及平均值，但本项目重点是消费记录列表的过滤、排序和分页。写入通常经过 refresh（刷新，使新数据可被搜索）后才可检索；ES 同步成功不能代替 MySQL 交易最终状态确认。
