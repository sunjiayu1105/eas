# 消息字段与事件身份

以下内容按照当前项目 `AGENTS.md` 项目级规则中规定的技术栈版本为准。

## 1 已确认规则

- 消息必须保留业务主键、操作类型、业务 `version`、原始 `create_time` 和操作所需数据。删除还需保留删除前的 `consumeId` 和原始 `create_time`。
- 消息拆分、重试和重新投递必须保持原事件的版本、数据、操作和来源身份不变。
- 事件级去重是否需要独立 `eventId` 尚待确认；RocketMQ 消息 ID 和 `keys` 不能单独作为稳定源事件身份。

## 2 面试口述精炼版本

消息要能说明是哪条记录、发生了什么操作，以及这次变更对应的版本。新增和更新携带业务主键、操作类型、业务 `version`、原始 `create_time` 和行后数据；删除携带删除版本、删除前的 `consumeId` 和原始 `create_time`。这些字段用于识别记录、保留事件上下文，并交给后续流程定位和写入。

## 3 详细方案

### 3.1 消息字段各自解决什么问题

以下是内部事件的逻辑要求，不代表 Canal 原生消息已经完整提供这些字段。

| 信息 | 用途 | 保持条件 |
|---|---|---|
| 业务主键及必要库表信息 | 识别业务记录及来源 | 明确主键唯一性范围，拆分重试不改变 |
| 操作类型 | 区分新增、更新和删除 | 同一事件重投不能改变操作 |
| 业务 `version` | 比较同一记录的新旧 | 新增、更新取行后值；删除也携带 version，其数据库生成和传递实现待验证 |
| 原始 `create_time` | 保留事件的原始创建时间，供 03 进行索引定位 | 不能用消息处理时间替换 |
| 行后业务数据 | 组装新增、更新的完整文档 | 是否包含所需字段须验证 |
| 删除前信息 | 保留 `consumeId`、原始 `create_time` 等定位数据 | 删除事件不存在可直接套用的“删除后行数据” |
| 必要来源信息、可选 `eventId` | 追踪来源或标识同一次变更 | 跨重新分批、重投和回放仍稳定 |

项目依据：[自定义消费服务的消息契约](<024_ES改造_自定义消费服务_自定义 ES 消费服务处理逻辑.md>)，支持业务版本读取、行数据要求与原始时间传递的设计边界。

### 3.4 可选事件身份与去重边界

“业务主键 + 业务版本”只有在主键范围明确、同版本对应同一次操作和同一内容时，才可作为事件识别的候选依据；不能忽略删除、主键复用与版本重置问题。

采用来源实例与 binlog 行坐标生成 `eventId` 也是候选方案。关联 Server 文档已经指出原生 JSON 缺少完整坐标、二进制按键拆行缺少原行序号等边界，不能直接假设拿到消息就能构造稳定事件 ID。来源身份及行级坐标必须先补齐并验证。

RocketMQ 消息 ID、`keys`、批次 ID 和分批下标不能单独保证源事件在重新发布、重新分批后的身份稳定。独立事件 ID 也不等于已经实现幂等；去重判断及处理结果见 [09 重复消息幂等](<010_ES写入链路_ES_09_重复消息幂等.md>)。

依据：Canal Server 原总览（原文档已删除，依据待补充）与 [消费服务的可选去重要求](<024_ES改造_自定义消费服务_自定义 ES 消费服务处理逻辑.md>)。
