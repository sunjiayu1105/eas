# 999_ES改造_ES_新表与 ES 增量校验_增量比较与版本判断

以下内容按照当前项目 `AGENTS.md` 项目级规则中规定的技术栈版本为准。

## 1 已确认规则

- 比较对象是扫描到的 MySQL 新表当前记录与 ES 对应文档，不建立独立校验任务。
- MySQL 记录不存在时不进入比较；DELETE 不在本流程处理。
- 查询失败只能记录异常并保留当前页游标，不能直接判定数据不一致。
- 版本相同且字段一致时比较成功；MySQL 版本高于 ES 时进入自动补偿；ES 高于本轮扫描版本时跳过本轮。
- 版本相同但字段不一致时记录差异，并按 MySQL 数据执行同版本补偿。

## 2 主题边界

本文只说明扫描记录与 ES 文档的读取、版本关系和比较结果。扫描入口见 [999](<./999_ES改造_ES_新表与 ES 增量校验_方案选择.md>)、扫描窗口见 [999](<./999_ES改造_ES_新表与 ES 增量校验_扫描窗口与回看.md>)、分页与进度见 [999](<./999_ES改造_ES_新表与 ES 增量校验_复合游标与轮次分页.md>)、[999](<./999_ES改造_ES_新表与 ES 增量校验_扫描任务持久化与调度.md>)；补偿、并发和恢复见 [999](<./999_ES改造_ES_新表与 ES 增量校验_自动补偿、并发与恢复.md>)。

## 3 面试口述精炼版本

扫描程序拿到 MySQL 当前仍存在的记录后，按 `consume_id` 查询 ES 对应文档，比较版本和业务字段。两端版本和字段都一致就通过；MySQL 版本更高说明 ES 落后，进入自动补偿；ES 高于本轮扫描结果，说明扫描结果可能过时，本轮跳过；版本相同但字段不同，记录差异并按 MySQL 数据做同版本补偿。查询失败不判定为数据差异，当前页不推进，下一轮继续。

## 4 比较结果

| 比较结果 | 处理方式 |
|---|---|
| MySQL 记录不存在 | 直接跳过，不查询 ES；DELETE 不进入本流程 |
| ES 文档不存在 | 记录 ES 缺失，进入自动补偿 |
| 版本相同且字段一致 | 标记当前记录校验成功，继续处理 |
| MySQL 版本高于 ES | 记录 ES 落后，按 MySQL 数据使用 `version_type=external` 补偿 |
| ES 版本高于本轮扫描结果 | 认为本轮 MySQL 扫描结果可能过时，跳过本轮，不覆盖 ES |
| 版本相同但字段不同 | 记录字段差异，按 MySQL 数据使用允许同版本覆盖的 `version_type=external_gte` 补偿 |
| MySQL 或 ES 查询失败 | 记录查询异常，保留当前页游标，下一轮重试 |

## 5 比较边界

扫描结果只代表本轮读取到的 MySQL 状态。ES 在比较前后可能被正常同步链路继续更新，因此：

- 不能用旧扫描结果覆盖版本更高的 ES；
- 版本相同字段不一致时才允许受控同版本补偿；
- 补偿写入仍受 ES 外部版本规则保护；
- 当前页处理结果全部成功后，045 才允许推进游标。
