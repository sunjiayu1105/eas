# 006_06 历史回放与 ILM 冷热迁移

## 1 已确认规则

1. 历史回放期间，相关索引绑定不含 cold 阶段的回放专用 ILM 策略。
2. 历史回放完成且新表与 ES 校验通过后，切换到包含 cold 阶段的正式策略。
3. `index.lifecycle.origination_date` 指定 ILM 计算索引年龄的起始时间，取索引所属自然月月初；计龄满 `400d` 后进入 cold。
4. `migrate` 只表示推动数据层迁移，进入 cold 不代表分片已经完成迁移。

以下内容按照当前项目 `AGENTS.md` 项目级规则中规定的技术栈版本为准。

## 2 面试口述精炼版本

历史回放不能让索引在数据尚未校验完成时进入 cold，因此回放期间使用只有 hot 阶段的专用策略。历史索引创建时把所属月份月初设置为 `origination_date`，这样补建的旧月份索引按历史月份计龄，而不是从补建当天重新计时。回放完成且新表与 ES 校验通过后，再切换到正式策略；正式策略按 `400d` 推进 cold。

## 3 详细方案

### 3.1 回放策略

```http
PUT /_ilm/policy/consume-replay
{
  "policy": {
    "phases": {
      "hot": { "actions": {} }
    }
  }
}
```

该策略不配置 cold、只读或删除动作。

### 3.2 创建历史索引

创建历史索引时显式绑定回放策略，并设置所属月份月初的时间戳。以下为未执行示例：

```http
PUT /records-2024.01
{
  "settings": {
    "index.lifecycle.name": "consume-replay",
    "index.lifecycle.origination_date": "1640966400000"
  }
}
```

`index.lifecycle.origination_date` 用于指定 **ILM 计算索引年龄的起始时间**。示例时间戳仅用于说明，实际值按索引所属月份和统一业务时区计算。[来源：ILM 设置](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/ilm-settings.html)

### 3.3 正式策略与切换

```http
PUT /_ilm/policy/consume-normal
{
  "policy": {
    "phases": {
      "hot": { "actions": {} },
      "cold": {
        "min_age": "400d",
        "actions": { "migrate": { "enabled": true } }
      }
    }
  }
}
```

回放和校验完成后，对仍处于回放策略 hot 阶段且没有未完成动作的索引切换策略：

```http
PUT /records-2024.01/_settings
{
  "index.lifecycle.name": "consume-normal"
}
```

已经进入 cold 或正在迁移的索引应先检查状态，不能把策略切换视为立即撤销动作。[来源：更新生命周期策略](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/update-lifecycle-policy.html)、[Migrate 动作](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/ilm-migrate.html)

### 3.4 状态检查与计龄

```http
GET /records-2024.01/_ilm/explain
```

检查实际策略、阶段、步骤和错误信息；迁移完成情况还需结合分片分配确认。各阶段 `min_age` 相对于 `origination_date` 计算，不会在进入上一阶段后重新计时。[来源：Explain lifecycle API](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/ilm-explain-lifecycle.html)
