# 006_05 索引设计、创建与写入

## 1 已确认规则

1. 项目使用 Elasticsearch 7.17.15，按不可变的原始 `create_time` 和统一业务时区计算 `records-yyyy.MM`，不使用 rollover。
2. 新增、更新、重试和补偿都写入原始创建时间所属的月份索引；`records-read` 只用于跨月查询。
3. 模板统一 Mapping、索引配置和读别名。索引不存在时，只有自动创建配置、模板匹配和权限均满足，首次 Index 写入才能自动创建索引。
4. 主链路使用 Index API 写入完整文档；业务版本只在同一物理索引、同一 `_id` 范围内比较，旧版本写入应被拒绝。
5. `upsert` 仅作为 Update API 的补充方案，当前主链路不以 Update API 代替完整文档写入。

以下内容按照当前项目 `AGENTS.md` 项目级规则中规定的技术栈版本为准。

## 2 面试口述精炼版本

项目没有采用参考文章中的 rollover，而是按自然月建立物理索引。应用使用不可变的原始创建时间计算月份，因此记录跨月更新时仍写入原来的索引，跨月查询使用 `records-read` 别名。

索引模板提前统一字段映射、配置和别名。目标索引不存在时，如果自动创建、模板匹配和权限都满足，首次 Index 请求会创建索引并写入完整文档。请求携带业务版本，用外部版本比较防止旧消息覆盖新消息；写入成功后还要等 refresh 才能被搜索看到。

## 3 详细方案

### 3.1 参考方案与项目方案

参考文章使用 Elasticsearch 8.4.2 的 rollover，在达到文档数等条件后滚动到下一代索引；其中 `response.version()` 不是项目业务版本。项目使用 Elasticsearch 7.17.15 的 `records-yyyy.MM` 自然月索引，不使用文章中的演示参数。月份决定数据归属，模板决定新索引结构，生命周期策略决定迁移和删除。

### 3.2 根据原始创建时间定位索引

同一条记录即使次月更新、重试或补偿，也继续操作原始创建时间所属的物理索引，不能使用当前处理时间重新计算月份。

```java
import java.time.Instant;
import java.time.ZoneId;
import java.time.format.DateTimeFormatter;

// originalCreateTime 是不可变的原始创建时间；businessZone 是统一业务时区。
String indexName = "records-" + originalCreateTime.atZone(businessZone)
        .format(DateTimeFormatter.ofPattern("yyyy.MM"));
```

历史导入、Canal、RocketMQ 和补偿链路必须保持同一个原始创建时间。若源字段是无时区的 MySQL `DATETIME`，业务时区和字段类型仍需确认。

### 3.3 模板与首次创建

模板匹配 `records-*`，统一核心 Mapping、索引配置和 `records-read` 别名。以下是未执行的核心示例：

```http
PUT /_index_template/records-template
{
  "index_patterns": ["records-*"],
  "template": {
    "settings": { "index.gc_deletes": "3h" },
    "mappings": {
      "properties": {
        "create_time": { "type": "date" },
        "version": { "type": "long" }
      }
    },
    "aliases": { "records-read": {} }
  }
}
```

`index.gc_deletes` 不控制 ILM 整索引删除，也不能防止被删除的月份索引因旧消息重建。实际 Mapping、模板优先级和 `dynamic` 配置需要继续核对。

### 3.4 Index API、版本和 Update API

更新先于新增到达时，应用仍按原始创建时间定位索引，并使用 Index API 写入完整文档。较新的版本先写入后，较旧版本在同一索引和 `_id` 下由 `version_type=external` 拒绝；版本冲突需要区分重复、过期和异常。

```http
PUT /records-2026.10/_doc/1001?version=1&version_type=external
{
  "create_time": "2026-10-15T02:00:00Z",
  "version": 1
}
```

如使用 Update API，文档存在时更新 `doc`；文档不存在且配置 `upsert` 时按 `upsert` 创建；未配置 `upsert` 时更新失败。当前项目主链路仍使用 Index API。

### 3.5 自动创建、权限和搜索可见性

自动创建至少依赖：`action.auto_create_index` 允许 `records-*`、账号拥有创建索引和写文档权限、模板正确匹配且字段符合 Mapping。带别名自动创建时，还要核对别名授权；模板管理权限应交给部署或运维账号。

写入成功不等于立即可搜索，文档要在 refresh 后才对搜索可见，是否同步等待由刷新策略决定。[来源：Index API](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/docs-index_.html)、[Update API](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/docs-update.html)、[权限列表](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/security-privileges.html#privileges-list-indices)。参考文章和项目方案必须区分，文章中的演示参数不能直接作为项目容量、保留期或生命周期配置。
