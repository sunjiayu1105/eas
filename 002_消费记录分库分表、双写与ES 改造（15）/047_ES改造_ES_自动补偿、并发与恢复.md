# 047_ES改造_ES_自动补偿、并发与恢复

以下内容按照当前项目 `AGENTS.md` 项目级规则中规定的技术栈版本为准。

## 1 已确认规则

- 明确差异由程序自动补偿，不进行人工补偿。
- 补偿前重新读取 MySQL 当前数据和当前版本，不能使用任务中的旧数据。
- 补偿请求成功标记“补偿完成”并结束；补偿失败保留未完成状态并继续重试。
- 同一业务记录使用 Redis 锁控制校验任务并发。
- ES 写入继续使用业务版本和外部版本控制，不能无版本覆盖。
- 补偿成功不再执行本任务的再次比较。

## 2 主题边界

本文只说明补偿、并发、任务状态和恢复。扫描入口见 [044](<./044_ES改造_ES_新表与 ES 增量校验方案选择.md>)，任务持久化见 [045](<./045_ES改造_ES_扫描任务持久化与调度.md>)，比较和版本判断见 [046](<./046_ES改造_ES_增量比较与版本判断.md>)。

## 3 面试口述精炼版本

确认 ES 落后后，程序先重新读取 MySQL 当前数据和版本，再按外部版本规则补偿 ES。写入成功标记“补偿完成”并结束，失败则保留未完成状态并重试。同一业务记录用 Redis 锁避免任务并发，版本控制防止旧数据覆盖新数据；进程重启后继续执行未完成任务。

## 4 自动补偿

补偿流程如下：

```text
确认 ES 落后或符合受控同版本规则
→ 重新读取 MySQL 当前记录、字段和 version
→ 确认记录仍可处理
→ 按当前 version 写入 ES
→ 成功：标记补偿完成并结束
→ 失败：保留未完成状态并按计划重试
```

补偿请求成功只表示 ES 接受了本次写入，因此任务状态是“补偿完成”，不写成“校验成功”。补偿成功后不再执行本任务的再次比较。

## 5 并发控制

同一业务记录使用 Redis 锁：

```text
lock:es-check:{source_instance}:{database}:{table}:{consume_id}
```

锁需要设置 TTL、支持续期，并在释放时校验持有者。Redis 锁只控制任务并发，不能替代 MySQL 当前版本读取和 ES 外部版本控制。

如果正常同步链路或其他任务已经写入更高版本，旧补偿写入必须被版本规则拒绝，不能把拒绝结果标记为成功。

## 6 任务状态与恢复

- 直接比较一致：校验成功；
- 补偿请求成功：补偿完成并结束；
- 查询失败、版本冲突或补偿失败：未完成，延迟重试；
- 任务版本已过时：记录过时并结束；
- 进程异常退出或锁过期：其他实例重新领取未完成任务，并重新读取 MySQL 当前状态。

重试需要保存下次执行时间、重试次数和失败原因，并通过退避避免故障期间形成高频重试。

## 7 待确认或待验证事项

- 补偿写入使用的外部版本类型与实际 ES 客户端行为；
- 同版本字段不一致时是否允许受控写入；
- Redis 锁 TTL、续期和异常释放；
- 补偿失败和长期未完成任务的退避、监控和容量。
