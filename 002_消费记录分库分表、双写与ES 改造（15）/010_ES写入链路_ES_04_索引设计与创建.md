# 索引设计与创建

以下内容按照当前项目 `AGENTS.md` 项目级规则中规定的技术栈版本为准。

## 1 已确认规则

- 本次按用户要求拆分职责：本文维护索引结构与创建前提，时间转换、目标索引计算和写入请求移至 03；保留示例、依据及待验证事项。
- 索引采用 `records-yyyy.MM` 自然月方案，不使用 rollover。记录归属取不可变的原始创建时间，业务时区为中国标准时间 UTC+08:00；读别名 `records-read` 仅用于查询。
- 模板统一 Mapping（字段映射）、公共配置和读别名；模板正确匹配是项目结构要求，不是 ES 自动创建的通用前提。
- 首次 Index 请求可在自动创建配置和权限允许时触发建索引；不会按日历主动建索引，Delete 请求不能承担索引初始化。
- 生命周期计龄与策略要求由 04、05 维护；本文负责说明创建时必须完成的配置衔接。配置示例未执行，不代表已部署。

## 2 面试口述精炼版本

我们按自然月组织索引，用原始创建时间确定数据归属，跨月查询使用读别名。索引模板统一字段映射和公共配置，避免每个月创建出来的索引结构不一致。

索引不存在时，首次 Index 请求可以触发自动创建，但要核对自动创建配置、账号权限以及生效模板。创建成功还不够：历史回放策略和每月不同的生命周期计龄起点也必须正确设置，这部分创建衔接仍需实现验证。每条事件怎样计算目标索引并执行写入，见 03。

## 3 详细方案

### 3.1 索引组织与职责交接

自然月索引定义数据归属，模板定义字段结构和公共配置，读别名提供跨索引查询入口。实际字段 Mapping 另见 [013 ES Mapping 设计](<013_ES Mapping 设计.md>)，本文保留创建所需的最小示例。

[03 物理索引定位与增删改](<010_ES写入链路_ES_05_物理索引定位与增删改.md>) 使用这些规则计算目标索引并执行操作；创建机制不决定过期事件是否应该被接收。

### 3.2 模板与创建配置

模板匹配 `records-*`，统一核心 Mapping、索引配置和 `records-read` 别名。以下是未执行的核心示例：

```http
PUT /_index_template/records-template
{
  "index_patterns": ["records-*"],
  "template": {
    "settings": { "index.gc_deletes": "3h" },
    "mappings": {
      "properties": {
        "create_time": { "type": "date" },
        "version": { "type": "long" }
      }
    },
    "aliases": { "records-read": {} }
  }
}
```

`index.gc_deletes` 不控制 ILM 整索引删除，也不能防止被删除的月份索引因旧消息重建。实际 Mapping、模板优先级和 `dynamic` 配置需要继续核对。上述模板只展示公共配置，没有包含 ILM 策略绑定和每月不同的 `origination_date`，不是完整建索引方案。不能将某个月的固定时间戳放入通用模板供所有月份复用；如何在首次写入前完成这些设置，仍需实现与验证。

[来源：索引模板](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/index-templates.html)说明模板在创建索引时的应用；[ILM 设置](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/ilm-settings.html)说明策略绑定及计龄起点。

### 3.3 自动创建与权限

自动创建需检查 `action.auto_create_index` 是否允许目标索引，以及账号是否具备创建索引和写文档所需权限。带读别名创建时还须核对别名授权。模板管理属于部署或运维职责，不能把模板管理权限与消费账号的运行权限混为一谈。

自动创建成功不能证明 Mapping、字段限制和生命周期设置符合项目要求。首次写入如何触发创建只在这里说明；请求构造及响应处理统一见 03。

依据：[Index API](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/docs-index_.html) 与 [权限列表](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/security-privileges.html)。沿用已有参考链接，本次未联网复核。

### 3.4 创建与生命周期的交接

通用模板不能为所有月份复用一个固定的 `index.lifecycle.origination_date`。每月起点按所属月份下个月 1 日零点设置；回放期使用回放策略，历史范围同步、校验及观察验收后再切换正式策略。具体期限、策略和示例由 [06 历史回放与 ILM](<010_ES写入链路_ES_06_历史回放与ILM冷热迁移.md>)、[05 保留期与删除](<010_ES写入链路_ES_07_索引保留期与删除.md>) 维护。

创建流程必须衔接这些要求，但“首次 Index 自动创建”如何完成按月设置仍未闭合；本次不擅自选择预创建或其他实现替代已确认方案。Kibana 图形界面与 Console 是配置入口，部署版本和实际提交过程未核验，不作为已部署事实。
