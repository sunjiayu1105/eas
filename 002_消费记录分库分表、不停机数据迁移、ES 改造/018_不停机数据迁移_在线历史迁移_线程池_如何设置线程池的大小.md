# 018_不停机数据迁移_在线历史迁移_线程池_如何设置线程池的大小

问题：如何为在线历史迁移设置线程池大小？

以下内容按照当前项目 AGENTS.md 项目级规则为准，使用 Java 8。本文为设计分析，参数未完成压测验证。

## 1 面试口述精炼版本

口述内容字符数：258

**先给出资源约束**

线程池大小不能按 300 个任务直接推导。要先看数据库可用连接、CPU、磁盘、锁等待，并为在线业务预留资源。

**逐步压测**

从 2 个工作线程开始，固定批次和事务方式，再比较 4 个线程；同时观察吞吐、批次耗时、连接等待、数据库负载和业务延迟。吞吐提升很小而业务指标变差时，退回较低并发。2 和 4 只是压测候选值。

## 2 详细方案

### 2.1 不能套固定公式

迁移是阻塞 JDBC 的数据库任务，线程数既受 CPU 影响，也受连接池、磁盘和锁竞争影响。单个线程不一定只占一个连接，多实例还要把各实例线程数合计。

### 2.2 压测步骤

1. 选定每批 500—1000 条的候选范围，固定字段大小、数据分布和事务方式。

2. 以 2 个线程建立基线，再测试 4 个线程。

3. 记录吞吐、批次耗时、队列等待、连接等待、CPU、磁盘、锁等待、在线延迟和错误率。

4. 吞吐不再提升或在线指标恶化时，降低线程数或延长批间等待。

### 2.3 安全调节

降低并发前先停止派发，等待在途批次在边界处完成并保存结果，再关闭旧线程池；确认线程池和数据库操作收尾后，以新的线程数恢复。不能只修改配置就认为并发已经下降。

## 3 已确认规则

- 线程池大小使用压测确定，不由任务总数直接推导。
- 性能参数必须给出具体数值或范围、单位、作用对象和取值状态。
- 2、4 个线程只是候选压测值。

## 4 待确认或待验证事项

- 连接池预算、数据库负载阈值和在线业务验收指标。
- 线程池动态调整、停止协议和压测结果。
