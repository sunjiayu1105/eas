# 043_分库分表_容量验证

## 1 问题

按商户分片后，怎样验证 32 个物理分片能承载未来的保留数据？

## 2 高级 Java 面试核心考点

按自然年保留窗口和年增长估算峰值。分别检查每实例和每张表的数据、索引与维护空间，再看热点商户是否让某个分片先达到瓶颈。 本题承接[消费记录的分库分表方案是怎样设计的？](<./039_分库分表.md>)。

## 3 面试口述版本

口述内容字符数：100

先估算本年度及之前四个自然年的保留量，按商户分布计算每个实例和每张表的数据、索引及维护空间。再用代表性负载验证峰值写入、查询耗时和维护窗口，重点看最热的分片。平均数只能作为估算起点，32 个分片的实际承载能力仍需演练。
