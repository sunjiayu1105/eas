# 049_业务双写_版本防覆盖

## 1 问题

同一条记录的两次修改具有相同的 update_time，同步又是乱序到达的，怎样防止旧数据覆盖新数据？

## 2 高级 Java 面试核心考点

业务乐观锁生成版本、同步写入的版本谓词、切写前后的版本归属、首次创建与重复请求的处理。 本题承接[业务双写如何保证旧表提交后，新表最终收到同一次变更？](<./048_业务双写.md>)。

## 3 面试口述版本

口述内容字符数：111

相同时间戳分不出两次更新的先后。由当前主写表在更新业务字段时一并递增 version，目标端只接受更高版本。同版本要核对内容。切写前旧表生成版本，切写后新表接续维护。新订单从 1 开始，重复请求在插入前直接返回当前处理结果，迁移和重试沿用原版本。
