# 036_MySQL到ES同步_消息发布与位点提交

## 1 说明

以下内容按照当前项目 `AGENTS.md` 项目级规则中规定的技术栈版本为准。

## 2 问题

RocketMQ 已收到消息，为什么 Canal 重启后还可能再次发送同一批变更？

## 3 高级 Java 面试核心考点

发送结果、批次确认和进度持久化的区别，以及从较早位置重读导致的重复投递。

## 4 面试口述版本

口述内容字符数：122

假设 Broker 已收到一批消息，Canal 还没把对应的采集进度可靠保存就宕机。重启时只能从上一次保存的位置继续，重读的日志里包含刚才已发出的变更，于是同一变更可能再次投递。消费者要按原记录的主键和版本处理重放。确认重复时还要核对内容，同版本字段不同要保留差异。

## 5 详细方案

假设一个批次拆成两条消息，第一条已经送达，第二条发送超时。超时留下的是未知结果。若该批次随后重放，第一条可能再次送达。即使全部发送都成功，批次确认后、本地游标可靠保存前宕机，也可能重读。生产端发送返回、Canal 确认批次和消费者完成 ES 写入各有自己的完成条件。实际发行包遇到非 SEND_OK 且未抛异常时如何处理仍待验证。[发送结果与提交条件](</D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/999_ES改造_Canal Server_Canal Server 同步 binlog 到 RocketMQ_RocketMQ发布与Canal批次确认.md:43>)
