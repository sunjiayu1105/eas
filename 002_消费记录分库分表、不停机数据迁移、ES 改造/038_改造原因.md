# 038_改造原因

## 1 问题

后台列表为什么适合从 MySQL 迁到 ES？

## 2 高级 Java 面试核心考点

按商户分片可以定位交易写入。跨商户筛选、排序和分页需要访问多个分片，查询副本可隔离这类负载。

## 3 面试口述版本

口述内容字符数：114

商户号能把交易请求定位到一个分片，后台列表却常要跨商户筛选、排序和分页。让每个分片先查、再合并结果，会占用交易库的连接和计算资源。我们把允许短暂延迟的列表查询交给 ES，交易写入仍走 MySQL。要求刚写完就能查到的请求，要保留能满足这一要求的读路径。
