## 2 问题

一般情况下，如何设置 Java 线程池的大小？

### 2.1 考点

1. 按可用 CPU 核数估算计算密集型任务的起始线程数。
2. 按计算和同步等待的时间估算阻塞任务的起始线程数。

### 2.2 答题范围

分别说明两类任务的公式，用同一份 CPU 预算举例，最后说明怎样验证起始值。

### 2.3 候选理由

材料提出按任务的等待与计算时间估算并发度。用相同的 CPU 预算比较两类任务，可以考查候选人能否解释线程数为什么不同。[线程池大小与任务积压原始材料](</D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/080_线程池大小与任务积压原始材料.md:1>)

### 3.1 主要做计算的任务

起始线程数 ≈ 分给线程池的 CPU 核数。假设扣除其他业务和预留算力后还有 4 核，做哈希计算就从 4 个线程开始测。[Zalando 工程文章 · 搜索 blocking coefficient，见等待时间接近零时的估算](<https://engineering.zalando.com/posts/2019/04/how-to-set-an-ideal-thread-pool-size.html>)

### 3.2 同步等待 I/O 的任务

起始线程数 ≈ 可用 CPU 核数 ×（1 + 平均阻塞等待时间 ÷ 平均计算时间）。假设每个任务计算 10 毫秒、等数据库 20 毫秒，就从 4 ×（1 + 20 ÷ 10）= 12 个线程起测。只计工作线程被占住的时间，排队或异步释放线程后的等待要扣除。最后结合下游连接容量和压测结果定值。[Java 8 ThreadPoolExecutor · Queuing 中的 Bounded queues](<https://docs.oracle.com/javase/8/docs/api/java/util/concurrent/ThreadPoolExecutor.html>) · [Zalando · 线程数公式与数据库连接池限制](<https://engineering.zalando.com/posts/2019/04/how-to-set-an-ideal-thread-pool-size.html>)

## 4 详细方案

用同一组有代表性的任务测量每个任务的线程 CPU 时间 C 和执行期间的阻塞等待时间 W。任务进入线程池之前或在工作队列中排队的时间要单独统计。线程平均占用一个核心的比例约为 C / (C + W)，所以候选线程数约为 CPU 预算 × (1 + W / C)。CPU 预算要考虑进程配额、同机其他负载和希望留出的余量。等待时间随并发增长时，重新测量。

以固定大小的池做对比，改变线程数时保持队列策略和负载一致。配置弹性池时还要看工作队列。核心线程都忙时，ThreadPoolExecutor 会先尝试入队，入队失败后才尝试扩到最大线程数。使用近似无界的队列时，单独调大 maximumPoolSize 往往起不到扩容作用。[Java 8 ThreadPoolExecutor](https://docs.oracle.com/javase/8/docs/api/java/util/concurrent/ThreadPoolExecutor.html)
