# 012_不停机数据迁移_在线历史迁移_批次状态控制

以下内容按照当前项目 `AGENTS.md` 项目级规则中规定的技术栈版本为准。本文为已确认方案及设计分析，具体实现和运行效果尚未验证。

## 1 问题

批次状态如何控制历史迁移的启动、暂停、完成和故障恢复？

## 2 高级 Java 面试核心考点

- 状态机与操作约束：用持久化状态控制请求，前端按钮不能替代后端校验。
- 并发启动与状态转换：启动检查和状态更新在同一个加锁事务中完成。
- 异步停止与恢复边界：收到暂停请求不等于执行结束，异常恢复必须先核实残留操作。

**启动看状态，检查和更新一起做**

**暂停先收尾，异常先处理**

收到暂停请求后先进入暂停中，停止新处理；任意任务失败也停止新处理并告警。等线程和数据库操作实际结束后，再根据完整任务表更新状态：全部成功是已完成，安全暂停且还有未完成任务是已暂停，失败或结果不明是异常待处理。异常由运维核实修复后恢复为已暂停，不能重启后直接当作未启动。任务完成后仍需数据一致性校验。

## 4 详细方案

### 4.1 启动时的状态转换

批次信息表保存整个批次的扫描上下界和控制状态，任务表保存各任务的范围、状态、确认进度和失败原因；不新增任务表批次 ID。批次状态表示这一组任务是否允许启动或正在收尾，单个任务状态表示该范围的处理结果，二者不能混用。

只有未启动、已暂停可以进入运行中。后端必须在同一个加锁事务中完成状态检查与变更，不能先检查、再单独更新；其他状态拒绝启动。本设计只允许一个迁移实例，不采用 Redis 锁。

首次启动须完整保存任务清单后才能执行；恢复启动沿用原范围、任务和各自确认进度。初始化与状态变更的事务边界由启动专题展开，不能因进程重启就把批次改回未启动。

锁与事务细节见 [启动互斥与初始化事务](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/013_不停机数据迁移_在线历史迁移_启动互斥与初始化事务.md>)，扫描边界和任务字段见 [任务范围划分](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/014_不停机数据迁移_在线历史迁移_任务范围划分.md>)，提交执行见 [线程池调度](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/015_不停机数据迁移_在线历史迁移_线程池调度.md>)。本文维护状态转换条件，不重复展开各专题实现。

### 4.2 暂停、结束和恢复的状态转换

| 触发条件 | 状态变化与处理 |
| --- | --- |
| 用户暂停 | 运行中原子改为暂停中，通知停止新处理，等待当前执行收尾 |
| 任意任务失败 | 立即停止新处理并告警，尝试保存暂停中及任务失败状态；数据库不可用也不能继续派发 |
| 实际执行已收尾，完整任务清单全部成功且没有未知结果 | 更新为已完成，随后进入数据一致性校验 |
| 实际执行已安全收尾，没有失败或未知结果，但仍有未完成任务 | 更新为已暂停，允许后续启动继续处理 |
| 存在失败、未知结果或无法确认残留执行 | 进入异常待处理，禁止直接启动；状态无法落库时由告警和人工核实兜底 |
| 运维完成修复并核实上次操作已结束 | 恢复为已暂停，再走正常启动检查；不自动接管、不重新初始化 |

暂停中表示“正在停止”，此时禁止重新启动；已暂停才表示“可以恢复”。正常全部成功会自动结束，无需手动暂停。

服务器重启不代表数据库中的原操作必然结束。运行中或暂停中状态残留时，必须先核实上一次迁移的线程、进程和数据库操作，再修复任务与批次状态。恢复细节及失败原因诊断见 [暂停与故障恢复](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/017_不停机数据迁移_在线历史迁移_暂停与故障恢复.md>)；Future 收集、完整清单汇总和零任务边界见 [完成结果判定](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/018_不停机数据迁移_在线历史迁移_完成结果判定.md>)；进度续跑和重复写入分别见 [断点续跑](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/020_不停机数据迁移_在线历史迁移_断点续跑.md>)、[重试幂等](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/021_不停机数据迁移_在线历史迁移_重试幂等.md>)。

### 4.3 页面操作与后端校验

| 批次状态 | 列表含义 | 启动按钮 | 暂停按钮 |
| --- | --- | --- | --- |
| 未启动 | 尚未完成初始化 | 可用 | 禁用 |
| 运行中 | 初始化已提交，正在准备提交或执行任务 | 禁用 | 可用 |
| 暂停中 | 正在等待任务和数据库操作收尾 | 禁用 | 禁用 |
| 已暂停 | 已安全收尾，可以继续处理 | 可用 | 禁用 |
| 已完成 | 完整任务清单全部成功 | 禁用 | 禁用 |
| 异常待处理 | 存在失败、未知结果或无法确认的残留执行 | 禁用 | 禁用 |

列表直接显示当前状态，不单独提供“查询状态”操作，也不增加异常恢复接口。启动、暂停接口仍校验数据库中的状态，前端按钮禁用只是操作提示，不能承担并发控制。例如页面仍显示已暂停，但另一个请求已经启动成功，后端应按最新运行中状态拒绝再次启动。

## 5 已确认规则

- 按启动检查、初始化或恢复、提交执行、暂停或失败、结果判定、修复重启顺序阐述。
- 页面只显示当前状态，提供启动和暂停操作；后端独立校验状态。
- 同一时刻只允许一个迁移实例；启动使用数据库行锁和批次状态，不使用 Redis 锁。
- 首次初始化一次性保存完整任务；恢复保留原扫描范围和各任务进度。
- 任意任务失败均停止新处理、告警并由运维排查，不自动重试。
- 安全收尾后才允许恢复；完整任务全部成功后还需一致性校验。
- 口述各主题提供对应详细方案导航，标明目标行号；调整后同步校验。
