## 1 面试口述精炼版本

口述内容字符数：172

**三个重点**

历史迁移按主键范围分批，参考调参范围为每批 500—1000 条，项目参数待压测。通过批次大小、并发度和处理速度控制迁移压力。每批成功后保存进度，任务中断时从最近一次成功进度继续。批次处理或进度保存失败时可能重复执行，所以写入必须幂等：重复 INSERT 不能产生重复记录，版本较旧的 UPDATE 不能覆盖新状态。具体范围和阈值仍需通过压测确定。

## 2 详细方案

### 2.1 批次范围与限流

迁移按旧表主键范围拆分批次。参考文章_04 第 3 节给出的单批数据范围是 500—1000 条，只能作为调参起点，不能直接视为项目固定配置。项目需要结合数据库负载、在线请求延迟和迁移吞吐，通过压测与演练确定批次范围、并发度、限流阈值和事务边界。

批次过小会增加网络往返，批次过大则会增加内存占用和单次失败的影响范围；并发过高会增加数据库 I/O 和 CPU 压力。运行期间应观察吞吐、延迟、错误数和数据库负载，必要时降低速度或暂停任务。暂停由调度器或控制台的暂停机制负责，不是进度保存自动产生的结果。

来源：[参考文章_04 第 3 节：批次处理与性能调优](</D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/999_不停机数据迁移_参考文章_04.md:319>)。具体参数尚未完成生产验证。

### 2.2 断点续跑

每批数据处理完成并确认成功后，才保存该批次的完成位置。任务恢复时，从最近一次成功保存的位置继续；没有保存成功的位置不能视为已完成。

如果数据已经写入新表，但进度保存失败，恢复任务可能再次读取同一批。这里分析的是数据写入成功、进度尚未保存成功的失败窗口；实际事务边界和保存协议待验证，不能仅凭进度记录认定不会重复处理。

### 2.3 失败重试与幂等

数据库错误、锁等待超时或死锁等异常发生时，批次标记为失败并重试；超过重试阈值要告警，不能把失败批次当成已完成。

重试可能再次执行 INSERT 或版本条件 UPDATE：

- 新表没有记录时，INSERT 必须受唯一键约束保护；遇到重复记录时重新读取并判断，不能生成重复交易。
- 新表已有记录时，只接受更大的业务版本；来源版本较旧或相等时不直接覆盖；相等版本仍存在字段差异时应排查，不能直接算修复成功。

因此，幂等性、版本条件和进度保存要配合使用：幂等性解决重复执行，版本条件防止旧数据覆盖新数据，进度保存提供恢复位置。

### 2.4 示例：写入成功，但进度保存失败

以下为故障恢复示例，不代表生产中已发生；假设当前批次内的记录已经写入新表，但任务尚未成功保存本批进度。

1. 任务中断后，从上一次成功保存的进度恢复，再次读取本批旧表当前数据。

2. 对已写成功的记录，唯一键阻止重复插入；发生冲突后，重新读取新表并按版本判断。

3. 例如新表已有版本 3，本次读到的迁移数据是版本 2，则拒绝覆盖；相同版本且内容相同则无需重复修改。

4. 本批全部处理成功后保存进度，再继续下一批。若再次失败，保留恢复位置，不能跳过未完成批次。

恢复重读时使用此次读取到的数据，不默认沿用上次失败时的旧快照。
## 3 已确认规则

- 批次限流、断点续跑和重试幂等是面试考察重点，口述时必须分别说明控制迁移压力、恢复进度和安全重复执行的机制。
- 批次数据量使用范围表达；参考文章的 500—1000 条只是调参起点，不是项目固定配置。
- 每批成功后保存进度；进度保存失败时允许重做，不能跳过批次。
- 迁移写入必须幂等，重复 INSERT 不能产生重复记录，旧版本 UPDATE 不能覆盖新版本。

## 4 待确认或待验证事项

- 项目最终批次范围、并发度、限流阈值和事务边界。
- 进度记录的实际存储、保存协议和恢复行为。
- INSERT 冲突、UPDATE 影响 0 行和超过重试阈值后的实际处理结果。
- 监控指标、告警阈值和暂停后恢复的具体操作。
