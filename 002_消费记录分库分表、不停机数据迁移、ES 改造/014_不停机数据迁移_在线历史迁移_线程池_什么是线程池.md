什么是线程池？

**先理解线程池是什么**

线程池是一种统一管理和复用线程的机制。任务是要做的工作，线程是执行任务的执行者。业务代码把任务交给线程池，由线程池安排线程执行，不必为每个任务单独创建线程。

**再看线程如何复用**

一个线程完成任务后，可以继续执行下一个任务。例如配置固定 1 个工作线程、队列容量为 1：A 正在执行，B 在队列等待；线程池保持运行且 A 正常完成后，同一个线程接着执行 B。

**最后明确创建时机**

线程池不一定提前创建好所有线程，也可以在任务到来时按需创建。具体创建多少、任务能否等待或被接收，取决于实现和配置。

## 3 详细方案

### 3.1 先区分任务和线程

例如，“迁移一段主键范围内的数据”是一个任务，工作线程负责执行这个任务。一个线程可以先后完成多个任务，所以任务数量不等于线程数量。线程池把任务提交与线程管理分开，业务代码描述要做什么，线程池安排由哪个工作线程执行。

### 3.2 示例：一个线程执行两个任务

以 ThreadPoolExecutor 为例，核心线程数和最大线程数均为 1，队列容量为 1，未预启动核心线程，采用 AbortPolicy（无法接收任务时抛出异常）。以下是机制示例，过程中线程池保持运行，任务正常完成。

1. 首次提交任务 A，线程池创建工作线程 T1，由 T1 执行 A。

2. A 尚未结束时提交 B，B 在队列等待。

3. A 正常完成后，T1 从队列取出 B 并执行，不再为 B 创建新线程。

这个过程说明任务结束不等于线程退出。线程也可能因异常、回收规则或关闭而退出，不能理解为永远存活。

### 3.3 按需创建不等于每次新建

以 Java 8 的 ThreadPoolExecutor 为例，默认不会在构造时启动所有核心线程，而是在接收任务时按规则创建；也可以显式预启动核心线程。已有线程能够继续执行任务时，可以复用它，不必再创建一个。

线程池不能接收任务时如何处理，由具体实现和拒绝策略决定；本例的 AbortPolicy 会抛出异常。线程复用也不负责保存业务进度或保证数据一致性。

### 3.4 技术依据

[Java 8 ThreadPoolExecutor API](https://docs.oracle.com/javase/8/docs/api/java/util/concurrent/ThreadPoolExecutor.html) 的核心线程创建、预启动和队列说明可供核对；本次未联网复核 API 页面。
