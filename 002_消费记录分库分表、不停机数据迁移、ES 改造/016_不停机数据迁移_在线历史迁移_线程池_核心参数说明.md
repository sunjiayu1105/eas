# 016_不停机数据迁移_在线历史迁移_线程池_核心参数说明

问题：ThreadPoolExecutor 的核心参数分别控制什么？

以下内容按照当前项目 AGENTS.md 项目级规则为准，使用 Java 8。本文为设计分析，示例未运行验证。

## 1 面试口述精炼版本

口述内容字符数：252

**线程数和队列**

corePoolSize 控制核心线程数，maximumPoolSize 控制最大线程数，workQueue 保存等待执行的任务描述。核心数等于最大数时，队列满后不会继续扩容。

**生命周期和拒绝**

keepAliveTime 控制非核心线程空闲回收，threadFactory 负责命名线程，handler 处理无法接收的任务。示例为核心/最大 2、队列 2、AbortPolicy，实际值需压测。

## 2 详细方案

### 2.1 参数表

| 参数 | 作用 | 示例 |
| --- | --- | --- |
| corePoolSize | 核心线程数 | 2 |
| maximumPoolSize | 最大线程数 | 2 |
| keepAliveTime | 非核心线程空闲回收 | 0 毫秒 |
| workQueue | 等待任务 | ArrayBlockingQueue(2) |
| threadFactory | 创建和命名线程 | 默认工厂 |
| handler | 队列满时处理 | AbortPolicy |

上述数值只是设计示例；队列只保存范围任务描述，不保存整批数据。

### 2.2 关键边界

线程数不等于任务总数，也不等于多实例全局并发。队列容量不等于吞吐保证，拒绝策略也不等于任务完成。实际值需结合连接预算、CPU、磁盘、锁等待和业务延迟压测。

## 3 已确认规则

- 参数必须给出数值、单位、作用对象和取值状态。
- 2 个线程、2 个队列容量和 0 毫秒均为示例，不是生产配置。

## 4 待确认或待验证事项

- 实际线程数、队列容量、线程工厂和拒绝策略。
- 线程池指标、数据库负载和业务阈值。
