# 020_不停机数据迁移_在线历史迁移_重试幂等

问题：历史迁移重复执行时，如何避免重复插入和旧版本覆盖新版本？

以下内容按照当前项目 AGENTS.md 项目级规则为准。本文是 011 的分文档，具体实现和运行效果尚未验证。

## 1 面试口述精炼版本

口述内容字符数：267

**插入防重复，更新防覆盖**

重试重新读取旧表当前数据和 version，按 merchantNo + serialNo 定位新表。没有记录就插入，唯一索引防止重复；已有记录只在 SQL 中接受更大的来源版本，业务字段和版本一起保存。

**结果要核实**

版本相同且字段相同可以安全跳过；版本相同但字段不同要记录异常。UPDATE 影响 0 行时要重新查询，区分记录缺失、版本较新和条件不满足，不能直接算成功。持续失败要告警，不能无限重试。

## 2 详细方案

### 2.1 插入与更新

新表没有记录时执行 INSERT，并依靠 merchantNo + serialNo 唯一约束防止重复创建。唯一键冲突后重新读取，再按版本判断；其他约束冲突不能直接覆盖。

新表已有记录时，在同一条 UPDATE 中比较版本，只接受来源 version 更大的数据，不先查询后无条件更新。迁移不生成新版本。

### 2.2 典型时序

1. 迁移第一次写入版本 2，但整批进度保存失败。

2. 重试再次读取版本 2；若新表也是版本 2 且字段相同，安全跳过。

3. 若双写已经把新表更新为版本 3，版本条件不满足，不能把版本 3 改回版本 2。

4. UPDATE 影响 0 行后，重新查询确认当前版本和字段，再决定补建、跳过或告警。

### 2.3 失败边界

数据库异常、锁等待、死锁和结果未知都保留失败状态；超过重试阈值告警。物理删除后目标不存在的迟到 INSERT 由一致性校验发现，不能把版本条件当成删除保护。

## 3 已确认规则

- 重复 INSERT 不能产生重复记录。
- 旧版本 UPDATE 不能覆盖新版本。
- 同版本字段差异不能直接算修复成功。
- 持续失败必须告警，不能无限重试。
