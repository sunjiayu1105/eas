## 2 详细方案

### 2.1 提交顺序与配置

Java 8 的 ThreadPoolExecutor 在运行状态下优先创建核心线程，再尝试入队；入队失败后尝试创建不超过 maximumPoolSize 的线程，仍不能接收时拒绝。关闭状态下也可能拒绝。

以下是 Java 8 配置片段，不是完整调度器，参数均为示例。

~~~java
int workers = 2;       // 核心数与最大数一致
int queueCapacity = 2; // 只保存范围任务描述
ThreadPoolExecutor pool = new ThreadPoolExecutor(
    workers, workers, 0L, TimeUnit.MILLISECONDS,
    new ArrayBlockingQueue<Runnable>(queueCapacity),
    Executors.defaultThreadFactory(),
    new ThreadPoolExecutor.AbortPolicy()
);
~~~

Executors.newFixedThreadPool 默认使用无界队列，固定线程数不能限制排队数量。专用线程池隔离业务线程，但不会自动隔离数据库连接和负载。

### 2.2 示例：运行数与排队数分开

1. A、B 分别由两个工作线程执行。

2. C、D 的任务描述进入队列，不提前读取整个主键范围。

3. E 再提交时触发拒绝。两个运行任务不计入队列容量。

每个范围任务平均约 100 万条有效记录，执行时按每批 500—1000 条参考目标读取，不能一次加载整个范围。keepAliveTime=0 毫秒是空闲线程存活配置；本例没有超出核心数的线程，且核心线程默认不超时。100 毫秒批间休眠须由任务内部另行执行。
