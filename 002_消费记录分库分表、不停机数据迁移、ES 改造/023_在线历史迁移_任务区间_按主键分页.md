## 2 问题

一个任务拿到主键区间后，怎样逐页读取流水？遇到主键不连续时，下一页从哪里开始？

### 2.1 考点

1. 说明第一页怎样包含区间起点，后续各页怎样按主键升序从上一页最后一条记录之后继续，并始终限制在本任务的上界内。
2. 用主键有空洞的例子说明如何找到下一条实际存在的记录，以及怎样判断区间已读完。

### 2.2 答题范围

接在 7.2 划定任务区间之后，讲一次正常执行中的分页。写成功但进度保存失败后的恢复由 7.4 展开。

### 2.3 候选理由

区间划分正确，分页条件仍可能重复读取页末记录或漏掉区间起点。这道题能检验候选人能否把扫描边界落实到每次读取。

- 项目依据　历史迁移按任务区间和主键分页，整页写入确认后保存页末主键。[区间内分页与页末主键](</D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/019_在线历史迁移.md:36>)

## 3 面试口述版本

口述内容字符数：167

每个任务只读分给自己的闭区间。第一页从区间起点开始，按主键升序取一页。整页写入确认并保存页末主键后，下一页只取主键大于该值、且不超过区间终点的记录。举个例子，区间是 100 到 110，实际只有 100、103、108 三条，每页取两条。第一页取 100 和 103，第二页从大于 103 的记录中取到 108。再次查询成功且没有剩余记录，这个任务就可以结束，即使最后一条的主键小于 110。

## 4 详细方案

以下 SQL 是分页条件示例。参数 page_size 表示单页最多读取的记录数，实际取值待确认。

~~~sql
-- 首次读取包含区间起点，两种查询都限制在任务上界内。
SELECT id FROM source_table
WHERE id >= :start_id AND id <= :end_id
ORDER BY id LIMIT :page_size;

-- 后续从已确认页末主键之后继续，避免重复读取上一页末行。
SELECT id FROM source_table
WHERE id > :last_id AND id <= :end_id
ORDER BY id LIMIT :page_size;
~~~

示例仅展示定位记录所需的主键。搬运时还需读取业务字段和来源版本。查询失败时保留已确认进度。区间如何划分见[任务区间](</D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/022_在线历史迁移_任务区间.md:1>)，失败后从哪里恢复见[断点续跑](</D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/026_在线历史迁移_断点续跑.md:1>)。
