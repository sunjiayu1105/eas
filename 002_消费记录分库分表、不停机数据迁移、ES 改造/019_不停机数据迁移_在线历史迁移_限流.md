# 019_不停机数据迁移_在线历史迁移_限流

以下内容按照当前项目 `AGENTS.md` 项目级规则中规定的技术栈版本为准。本文为已确认方案及设计分析，具体实现和运行效果尚未验证。

## 1 问题

历史迁移如何通过限制并发和分页请求频率，避免持续占满数据库资源？

## 2 高级 Java 面试核心考点

- 并发数与请求频率分别控制，同时约束数据库压力。
- 分页间等待降低持续访问频率，但不保证精确 QPS。
- 根据在线负载安全调整，区分参数示例与生产配置。

## 3 面试口述精炼版本

**先限制同时执行的任务数**

用核心数和最大数均为 N 的固定线程池，让最多 N 个范围任务同时访问数据库；一个任务内部按页顺序处理。N 根据数据库预算压测确定，不能按任务总数直接设定。

详见：[并发限制与页大小（第 33 行）](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/019_不停机数据迁移_在线历史迁移_限流.md:33>)。

**再控制持续访问频率**

每页写入结果确认并保存进度后，等待配置的时间，再读取下一页。例如 2 个线程、每页最多 500 条、分页间等 100 毫秒，只是测试示例。在线延迟或数据库压力过高时，可延长等待，或暂停并确认执行收尾后降低并发；这种等待不能保证精确固定的每秒写入条数。

## 4 详细方案

### 4.1 并发限制与页大小

当前只允许一个迁移实例，用固定 N 个线程限制同时处理的范围任务数，一个任务内部不再创建额外迁移线程。N 为可配置正整数，生产取值待压测；线程池配置与内存预算见 [线程池调度](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/015_不停机数据迁移_在线历史迁移_批次处理逻辑_线程池调度.md>)，候选线程数对照方法见 [线程数选择](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/016_不停机数据迁移_在线历史迁移_批次处理逻辑_线程池调度_线程数选择.md>)。

任务总数表示总工作量，页大小表示单次最多读取多少条，线程数表示同时处理多少个范围，三者不能混为同一个参数。范围划分由 [任务范围划分](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/014_不停机数据迁移_在线历史迁移_批次处理逻辑_任务范围划分.md>) 维护；按主键游标和 LIMIT 读取、保存进度见 [断点续跑](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/020_不停机数据迁移_在线历史迁移_断点续跑.md>)。

页大小影响单次资源占用，分页间等待影响请求间隔。每页 500—1000 条是参考调参目标，实际取值需结合字段大小、驱动缓冲和数据库负载测试。分页大小、索引与事务提交的取舍由 [批次性能调优](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/022_不停机数据迁移_在线历史迁移_批次性能调优.md>) 维护，不能用增加等待代替检查单次慢查询或长事务。

### 4.2 分页间等待

每个任务完成本批写入并保存进度后，等待配置的时长，再读取下一批。这会降低单个任务连续访问数据库的频率。并发任务数限制“同时有多少任务在跑”，批间等待限制“每个任务跑得多快”。

参考文章只写了“每批之间短暂休眠”的注释，没有实际等待语句或具体时长；不能把该示例视为已实现限流。项目需要补充等待和中断处理，等待时长通过压测确定。批间等待需要提供可调整的配置；具体阈值与调参验证由性能调优分文档维护，不假定已有自动调节能力。此方式不能保证精确固定的每秒写入条数。

**示例：任务分开跑，每个任务分批等**

以下范围和等待时长仅用于解释机制，不是项目配置。

1. 任务 A 负责主键 1—1000000，任务 B 负责 1000001—2000000，两者没有重叠。

2. 假设每页最多读取 500 条，且示例范围内主键连续，A 首批读取 1—500，B 首批读取 1000001—1000500。主键有空洞时按实际返回记录的最后 ID 保存进度，不把每页条数当作固定主键跨度。

3. 各自确认本批结果并保存进度后，等待 100 毫秒再读下一批。两个任务可以同时运行，但每个任务都不会连续不停地发请求。

4. 数据库压力偏高时，可减少同时运行的任务数，或延长批间等待；如何安全让任务退出，由线程池分文档展开。

来源：[参考文章_04：批间休眠](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/ref_不停机数据迁移_参考文章_04.md:301>)、[并发度控制](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/ref_不停机数据迁移_参考文章_04.md:320>)。

### 4.3 安全调整与适用边界

当前设计在一次运行中保持线程数 N 不变。需要调整时先暂停，核实任务与数据库操作结束，再用新配置恢复；修改配置不代表在途请求已经停止。暂停与故障恢复完整协议见 [暂停与故障恢复](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/017_不停机数据迁移_在线历史迁移_批次处理逻辑_暂停与故障恢复.md>)。

等待时也应响应停止信号；中断等待后转入安全收尾，不能吞掉中断继续读取下一页。具体等待实现、信号通知和生产时长仍待验证，不宣称已有自动调速能力。

实例内固定线程数不自动限制多个进程的总并发。本方案通过批次启动控制只允许运行一个迁移实例；未来若采用两个各 2 个线程的实例，总并发可达 4，需要另行设计全局限制。参考文章_04 只提出范围并行及根据负载调节，并未给出这些 Java 调度保障。

## 5 已确认规则

- 不同任务处理互不重叠的主键范围。
- 约 3 亿条是数据规模背景；范围按固定 ID 跨度划分，任务数由跨度决定。
- 区分任务总数、并发数量和单批大小。
- 任务并发和批间等待都必须给出具体数值或范围，并标明示例或待压测状态。
