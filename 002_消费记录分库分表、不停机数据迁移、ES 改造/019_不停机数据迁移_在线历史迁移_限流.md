## 1 问题

如何控制历史迁移的任务范围、并发数量和请求频率？

## 2 高级 Java 面试核心考点

- 区分任务范围、单页大小与并发数。
- 固定并发与分页间等待配合限制数据库压力。
- 单实例范围内限流，不将局部线程数当作全局限制。

## 4 详细方案

### 4.1 先结合总量划分任务范围

旧表约 3 亿条、主键递增是项目背景，不是本次查询结果。当前按每段 100 万 ID 跨度拆分闭区间；记录数与 ID 跨度不同，只有总跨度约 3 亿时任务数才约 300。完整边界算法见 [任务范围划分](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/014_不停机数据迁移_在线历史迁移_批次处理逻辑_任务范围划分.md>)。

任务范围决定负责哪些数据，单页大小决定每次最多读取多少条，并发数决定同时运行多少个范围任务，三者不能混为一个参数。

### 4.2 任务内部再分批

迁移按旧表主键范围拆分批次。参考文章_04 第 3 节建议从 500—1000 的批次参数开始测试；本文沿用每批 500—1000 条的参考目标，只能作为调参起点，不能直接视为项目固定配置。具体调参方法与事务大小的取舍由性能调优分文档维护。

文章示例按起止主键划定区间，而不是按实际返回条数分页；主键有空洞或记录已删除时，区间内记录会少于预期。例如区间 [1001, 1500] 的宽度是 500，但只剩 420 条记录时，本批实际读取 420 条。边界不得漏掉主键；项目任务采用闭区间，任务内部按主键游标和 LIMIT 分页，具体见 [断点续跑](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/020_不停机数据迁移_在线历史迁移_断点续跑.md>)。来源：[参考文章_04：区间计算与读取（第 273 行）](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/ref_不停机数据迁移_参考文章_04.md:273>)。

任务范围划分后，由固定线程池限制同时运行的任务数；任务内部在批次之间等待。两层控制配合，才能同时限制并发数量和访问频率。

批次大小和并发数如何选择、如何利用索引及控制事务大小，统一见[022 批次性能调优](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/022_不停机数据迁移_在线历史迁移_批次性能调优.md>)。本文保留限流执行机制，不重复展开性能取舍。

### 4.3 并发度如何控制

例如用核心数和最大数均为 2 的固定线程池执行互不重叠的范围任务，限制同时访问数据库的任务数；一个任务内部仍按批次顺序处理。2 个线程只是示例，实际配置待压测；线程数不等于约 300 个任务的总数，也不能直接由总记录数确定。

线程池、队列容量和拒绝处理见 [015 线程池调度](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/015_不停机数据迁移_在线历史迁移_批次处理逻辑_线程池调度.md>)；安全停止见 [暂停与故障恢复](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/017_不停机数据迁移_在线历史迁移_批次处理逻辑_暂停与故障恢复.md>)。参考文章_04 仅提出多任务处理不同范围及按负载调整并发，没有给出这些 Java 实现。

### 4.4 批间等待如何控制

每个任务完成本批写入并保存进度后，等待配置的时长，再读取下一批。这会降低单个任务连续访问数据库的频率。并发任务数限制“同时有多少任务在跑”，批间等待限制“每个任务跑得多快”。

参考文章只写了“每批之间短暂休眠”的注释，没有实际等待语句或具体时长；不能把该示例视为已实现限流。项目需要补充等待和中断处理，等待时长通过压测确定。批间等待需要提供可调整的配置；具体阈值与调参验证由性能调优分文档维护，不假定已有自动调节能力。此方式不能保证精确固定的每秒写入条数。

**示例：任务分开跑，每个任务分批等**

以下范围和等待时长仅用于解释机制，不是项目配置。

1. 任务 A 负责主键 1—1000000，任务 B 负责 1000001—2000000，两者没有重叠。

2. 假设每页最多读取 500 条，且示例范围内主键连续，A 首批读取 1—500，B 首批读取 1000001—1000500。主键有空洞时按实际返回记录的最后 ID 保存进度，不把每页条数当作固定主键跨度。

3. 各自确认本批结果并保存进度后，等待 100 毫秒再读下一批。两个任务可以同时运行，但每个任务都不会连续不停地发请求。

4. 数据库压力偏高时，可减少同时运行的任务数，或延长批间等待；如何安全让任务退出，由线程池分文档展开。

来源：[参考文章_04：批间休眠](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/ref_不停机数据迁移_参考文章_04.md:301>)、[并发度控制](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/ref_不停机数据迁移_参考文章_04.md:320>)。

### 4.5 合计限制所有执行者

当前只允许一个迁移实例，总并发等于该实例的固定线程数 N。若未来采用两个各有 2 个线程的实例，总并发可达 4，必须重新设计全局限制；这是扩展边界，不是当前部署方案。

### 4.6 示例：执行者失去响应

A 处理范围 R 时失去响应，不能仅凭超时把 R 交给 B，否则 A 恢复后可能继续写入。本方案不自动接管，先由运维确认上一次线程与数据库操作结束，再恢复状态，具体见 [暂停与故障恢复](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/017_不停机数据迁移_在线历史迁移_批次处理逻辑_暂停与故障恢复.md>)。

### 4.7 部署与验证边界

当前采用单实例迁移设计，具体部署、启动互斥与暂停通知仍待验证。参考文章_04 第 320 行只说明范围并行和按数据库负载调整并发，未提供项目的 Java 调度和恢复实现。

## 5 已确认规则

- 不同任务处理互不重叠的主键范围。
- 约 3 亿条是数据规模背景；范围按固定 ID 跨度划分，任务数由跨度决定。
- 区分任务总数、并发数量和单批大小。
- 任务并发和批间等待都必须给出具体数值或范围，并标明示例或待压测状态。
