## 2 问题

一条 Canal 消息里有多行更新，每行写入 ES 的版本从哪里取？

## 3 高级 Java 面试核心考点

**答题范围** 说明主写表怎样生成业务版本，迁移、双写及重投怎样保留原版本，消费者如何逐行读取更新后的字段并使用各行的版本写入 ES。

**入选理由** 上一级题考查乱序写入怎样被拒绝。本题考查写入条件从哪一行取得，以及怎样避免把 MQ 消息标识、日志位置或其他行的版本当作本行版本。

**项目依据** 基于项目拟题。[项目原文](</D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/045_自定义消费服务.md:263>)

## 4 面试口述版本

口述内容字符数：157

当前主写表更新业务字段时，同时递增这笔流水的业务版本。迁移、双写和消息重投沿用原版本。收到一条包含多行更新的 FlatMessage 时，消费者从 data 逐行读取更新后的主键、原始创建时间和 version。用原始创建月份与主键定位 ES 文档，再把这行自己的 version 作为外部版本传给 ES。字段缺失时先核对消息契约，不用整条消息的编号替代。

[详细方案（第 27 行）](</D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/047_自定义消费服务_并发乱序_逐行取得业务版本.md:27>)

## 5 详细方案

首次创建由当前主写表写入版本 1，后续在同一次业务更新中递增。FlatMessage 的 old 是旧值信息，更新后的字段从 data 读取。重投仍需原目标月份、主键和业务版本。ES 只在同一物理索引和同一文档 ID 上比较版本。应使用实际多行 UPDATE 样本核对数据类型、字段完整性，以及记录更新前后值是否与写入一致。[消费服务的消息契约](</D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/045_自定义消费服务.md:1>) · [ES 7.17 Index API](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/docs-index_.html)
