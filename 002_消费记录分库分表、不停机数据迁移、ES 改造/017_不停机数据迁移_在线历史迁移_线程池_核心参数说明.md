# 017_不停机数据迁移_在线历史迁移_线程池_核心参数说明

## 1 问题

ThreadPoolExecutor 的核心参数分别控制什么？

以下内容按照当前项目 `AGENTS.md` 项目级规则中规定的技术栈版本为准。具体实现和运行效果尚未验证。

## 2 面试口述精炼版本

口述内容字符数：193

**线程数和队列**

corePoolSize 控制核心线程数，maximumPoolSize 控制最大线程数，workQueue 保存等待执行的任务描述。核心数等于最大数时，队列满后不会继续扩容。

**生命周期和拒绝**

keepAliveTime 控制非核心线程空闲回收，threadFactory 负责命名线程，handler 处理无法接收的任务。示例为核心/最大 2、队列 2、AbortPolicy，实际值需压测。

## 3 详细方案

### 3.1 ThreadPoolExecutor 参数

构造函数参数依次是 `corePoolSize`、`maximumPoolSize`、`keepAliveTime`、时间单位、工作队列、线程工厂和拒绝策略。

| 参数 | 作用 | 示例值及状态 |
| --- | --- | --- |
| `corePoolSize` | 核心线程数 | 2，同时处理两个范围任务；示例值 |
| `maximumPoolSize` | 最大线程数 | 2，与核心数相同，固定单进程并发；示例值 |
| `keepAliveTime` | 非核心线程空闲回收时间 | 0 毫秒；核心数等于最大数且未启用核心线程超时；示例值 |
| `unit` | 空闲回收时间单位 | `TimeUnit.MILLISECONDS`，毫秒 |
| `workQueue` | 暂存未执行任务 | `ArrayBlockingQueue<>(2)`，只存任务描述；示例值 |
| `threadFactory` | 创建并命名线程 | 示例使用默认工厂；自定义命名接入待确认 |
| `handler` | 无法接收任务时的处理 | `AbortPolicy` 显式拒绝；设计建议 |

核心数等于最大数时，队列满后不会继续扩容，单进程执行数固定在 2 以内。队列容量 2 只表示暂存两个任务描述，不代表最佳配置。

```java
int workers = 2;       // 示例值，实际取值需压测
int queueCapacity = 2; // 只保存任务描述
ThreadFactory factory = Executors.defaultThreadFactory(); // 此示例使用默认命名

ThreadPoolExecutor pool = new ThreadPoolExecutor(
    workers,
    workers,
    0L,
    TimeUnit.MILLISECONDS,
    new ArrayBlockingQueue<Runnable>(queueCapacity),
    factory,
    new ThreadPoolExecutor.AbortPolicy()
);
```

以上为方法内片段，所用类来自 java.util.concurrent 包，需补齐对应 import。代码只说明线程池构造方式，不包含调度、进度持久化、异常上报和关闭流程。线程数、队列容量和数据库预算由 [019 如何设置线程池的大小](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/019_不停机数据迁移_在线历史迁移_线程池_如何设置线程池的大小.md>) 通过压测确定。

参数依据：[ThreadPoolExecutor Java 8 API](https://docs.oracle.com/javase/8/docs/api/java/util/concurrent/ThreadPoolExecutor.html)。
