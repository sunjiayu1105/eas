## 3 面试口述版本

口述内容字符数：194（不计参考链接）

我先让这个池暂时不接任务，在有代表性的高峰时段连续观察几个窗口。服务跑在容器里时，以容器的 CPU 配额和同一容器的用量为准。

其他业务平均占用核数 ≈ 窗口内累计使用的 CPU 时间 ÷ 窗口时长。多个核能同时工作，所以 10 秒内累计用掉 30 秒 CPU 时间，相当于平均占了 3 核。[Kubernetes 资源指标文档 · Measuring resource usage / CPU](<https://kubernetes.io/docs/tasks/debug/debug-cluster/resource-metrics-pipeline/#cpu>)

线程池可用核数 ≈ 实例可用核数 − 其他业务占用核数 − 预留核数。假设实例可用 8 核，再留 1 核应对波动，预算就是 8 − 3 − 1 = 4 核。实际留多少，要看高峰波动和压测期间原有业务的响应时间。
