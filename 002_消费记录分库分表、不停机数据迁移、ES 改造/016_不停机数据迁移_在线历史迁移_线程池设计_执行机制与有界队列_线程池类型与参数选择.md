## 1 面试口述精炼版本

**明确选择理由**

迁移需要限制执行数和积压量，建议直接构造 ThreadPoolExecutor，显式设置线程数、有界队列和拒绝策略。

**配置相互配合**

示例核心数和最大数均为 2，队列容量 2；两个任务运行时，可再暂存两个任务描述。容量耗尽后由 AbortPolicy 抛出异常，调度方保留任务。核心线程默认不超时，因此本例空闲回收时间设为 0 毫秒。

**避开默认配置风险**

固定线程池默认无界排队，缓存线程池可能大量创建线程，都不适合直接作为迁移资源上限。上述参数只是设计示例，实际值需按数据库容量压测。

## 2 详细方案

### 2.1 线程池与实现类

线程池复用工作线程，把任务提交和执行管理分开。工作线程完成一个范围任务后继续取得下一个任务，避免为约 300 个范围任务各创建一个线程。

线程池只负责执行层的并发和生命周期管理，不能代替进度持久化、幂等、事务或多实例任务领取。

Java 8 的 `ThreadPoolExecutor` 可以显式配置核心线程数、最大线程数、有界队列、线程工厂和拒绝策略，适合本迁移的资源控制要求。

### 2.2 常用线程池的取舍

共同点是复用工作线程执行任务；差别在于线程数量、排队方式和调度时机。

**固定线程池：** `newFixedThreadPool(n)` 固定线程数，但默认使用无界 `LinkedBlockingQueue`，任务持续提交时可能积压大量任务。

**单线程执行器：** `newSingleThreadExecutor()` 串行执行，适合必须单线程处理的任务，但不能替代多实例全局并发控制。

**缓存线程池：** `newCachedThreadPool()` 可能持续创建线程，数据库变慢时不适合作为迁移并发上限。

**定时线程池：** `newScheduledThreadPool(n)` 适合延迟或周期触发；耗时迁移仍应交给独立工作池。

**ForkJoinPool：** 适合可拆分的计算任务；阻塞 JDBC 场景不能把目标并行度当作数据库访问上限。

来源：[Executors Java 8 API](https://docs.oracle.com/javase/8/docs/api/java/util/concurrent/Executors.html) 和 [ForkJoinPool Java 8 API](https://docs.oracle.com/javase/8/docs/api/java/util/concurrent/ForkJoinPool.html)。

### 2.3 ThreadPoolExecutor 参数

构造函数参数依次是 `corePoolSize`、`maximumPoolSize`、`keepAliveTime`、时间单位、工作队列、线程工厂和拒绝策略。

| 参数 | 作用 | 示例值及状态 |
| --- | --- | --- |
| `corePoolSize` | 核心线程数 | 2，同时处理两个范围任务；示例值 |
| `maximumPoolSize` | 最大线程数 | 2，与核心数相同，固定单进程并发；示例值 |
| `keepAliveTime` | 非核心线程空闲回收时间 | 0 毫秒；核心数等于最大数且未启用核心线程超时；示例值 |
| `unit` | 空闲回收时间单位 | `TimeUnit.MILLISECONDS`，毫秒 |
| `workQueue` | 暂存未执行任务 | `ArrayBlockingQueue<>(2)`，只存任务描述；示例值 |
| `threadFactory` | 创建并命名线程 | 示例使用默认工厂；自定义命名接入待确认 |
| `handler` | 无法接收任务时的处理 | `AbortPolicy` 显式拒绝；设计建议 |

核心数等于最大数时，队列满后不会继续扩容，单进程执行数固定在 2 以内。队列容量 2 只表示暂存两个任务描述，不代表最佳配置。

```java
int workers = 2;       // 示例值，实际取值需压测
int queueCapacity = 2; // 只保存任务描述
ThreadFactory factory = Executors.defaultThreadFactory(); // 此示例使用默认命名

ThreadPoolExecutor pool = new ThreadPoolExecutor(
    workers,
    workers,
    0L,
    TimeUnit.MILLISECONDS,
    new ArrayBlockingQueue<Runnable>(queueCapacity),
    factory,
    new ThreadPoolExecutor.AbortPolicy()
);
```

以上为方法内片段，所用类来自 java.util.concurrent 包，需补齐对应 import。代码只说明线程池构造方式，不包含调度、进度持久化、异常上报和关闭流程。线程数、队列容量和数据库预算由 [013 性能调优](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/013_不停机数据迁移_在线历史迁移_性能调优.md>) 通过压测确定。

参数依据：[ThreadPoolExecutor Java 8 API](https://docs.oracle.com/javase/8/docs/api/java/util/concurrent/ThreadPoolExecutor.html)。

### 2.4 取值边界

线程池大小不能由约 300 个范围任务直接推导。还要考虑数据库连接预算、CPU、磁盘、锁竞争、在线业务预留和多实例总并发。增加线程可能只增加连接等待，因此需要同时观察吞吐、任务耗时、队列等待、数据库负载和业务延迟。
