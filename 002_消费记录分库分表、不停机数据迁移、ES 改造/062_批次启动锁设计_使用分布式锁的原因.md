# 062_批次启动锁设计_使用分布式锁的原因

## 1 问题

已有数据库状态条件更新，为什么还在批次启动入口使用分布式锁？

## 2 高级 Java 面试核心考点

本地锁只能协调单个实例内的请求。批次锁让竞争失败的请求在开启事务前返回，减少同一批次争用数据库的机会。 本题承接[同一批次的首次启动和恢复请求怎样竞争同一把锁，锁应该持有到哪一步？](<./061_批次启动锁设计.md>)。

## 3 面试口述版本

口述内容字符数：107

两个应用实例有各自的 JVM，本地锁拦不住另一个实例。它们用同一批次 ID 竞争同一个 Redis 锁，失败者在开启数据库事务前就返回，因此减少同一行上的锁等待。代价是启动依赖 Redis。批次状态能否改变仍由数据库条件更新和事务提交决定。
