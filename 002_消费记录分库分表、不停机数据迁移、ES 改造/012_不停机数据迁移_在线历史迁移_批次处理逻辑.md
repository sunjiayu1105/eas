## 1 问题

不停机历史迁移中，批次如何启动、执行、暂停和恢复，并判断何时完成？

## 2 高级 Java 面试核心考点

- 批次状态机：明确允许启动、暂停及结束的条件。
- 流程衔接：初始化提交后执行任务，安全收尾后才能恢复。
- 完成边界：任务全部成功与数据一致性校验通过分开判断。

## 4 详细方案

### 4.1 批次执行顺序

1. 锁定同一批次记录并检查启动条件；阻止运行中、暂停中、已完成或异常待处理的批次重复启动。详见 [启动互斥与初始化事务](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/013_不停机数据迁移_在线历史迁移_批次处理逻辑_启动互斥与初始化事务.md>)。
2. 首次查询旧表 MIN/MAX，固定本批次扫描边界，生成完整任务清单并与运行中状态一起提交；恢复时不重新初始化。任务边界与字段见 [任务范围划分](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/014_不停机数据迁移_在线历史迁移_批次处理逻辑_任务范围划分.md>)。
3. 提交确认后查询待处理、已暂停任务，交给专用固定线程池。正在运行的任务按页处理；线程数、队列和拒绝处理见 [线程池调度](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/015_不停机数据迁移_在线历史迁移_批次处理逻辑_线程池调度.md>)，各任务进度见 [断点续跑](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/020_不停机数据迁移_在线历史迁移_断点续跑.md>)。
4. 用户暂停或任意任务失败时，停止新处理并等待实际执行收尾。失败立即告警，不等待调度线程读到异常后才停止。详见 [暂停与故障恢复](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/017_不停机数据迁移_在线历史迁移_批次处理逻辑_暂停与故障恢复.md>)。
5. 核对完整任务表后更新批次状态；正常全部成功自动结束，不需要手动暂停。详见 [完成结果判定](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/018_不停机数据迁移_在线历史迁移_批次处理逻辑_完成结果判定.md>)。
6. 运维修复失败或宕机残留状态后，再走相同启动检查，各任务从原确认进度继续。重复页写入仍需 [重试幂等](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/021_不停机数据迁移_在线历史迁移_重试幂等.md>)。

### 4.2 批次状态和页面操作

批次信息表保存批次状态和整个批次的扫描上下界，任务表保存各任务的扫描范围、状态和处理进度。批次状态用于控制启动和暂停，直接展示在批次列表中；不新增任务表批次 ID。建议状态如下：

| 状态 | 含义 |
| --- | --- |
| 未启动 | 尚未完成初始化；首次启动需在事务中保存完整清单 |
| 运行中 | 初始化已提交，正在准备提交或执行任务，允许暂停 |
| 暂停中 | 已收到暂停或失败信号，正在等待任务和数据库操作收尾 |
| 已暂停 | 本次已安全收尾，可以再次启动 |
| 已完成 | 完整任务清单全部成功 |
| 异常待处理 | 存在失败、未知结果或无法确认的残留执行，需运维处理 |

批次列表直接显示当前状态，不设置单独的“查询状态”操作。未启动、已暂停时仅启动可用；运行中时仅暂停可用；暂停中、已完成和异常待处理时两个按钮都禁用。后端仍须校验状态并防止重复启动，不能只依赖前端置灰。服务器重启后不得直接把运行状态重置为未启动，应确认上一次迁移的线程和数据库操作已结束，并处理残留任务后再允许启动。

### 4.3 职责和验证边界

本设计同一时刻只允许一个迁移实例，不采用 Redis 锁，也不自动接管失去响应的执行。[启动互斥与初始化事务](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/013_不停机数据迁移_在线历史迁移_批次处理逻辑_启动互斥与初始化事务.md>) 负责短事务启动互斥，[暂停与故障恢复](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/017_不停机数据迁移_在线历史迁移_批次处理逻辑_暂停与故障恢复.md>) 负责恢复前确认上次执行结束。线程池不能替代二者。

示例：任务 A 已成功、B 失败、C 仍在运行时，立即告警并停止新处理，但必须继续等待 C 收尾；不能因已判失败就启动第二组任务。所有任务成功后仍按 [完成结果判定](<D:/000/sources/eas/002_消费记录分库分表、不停机数据迁移、ES 改造/018_不停机数据迁移_在线历史迁移_批次处理逻辑_完成结果判定.md>) 区分执行成功与数据一致。

## 5 已确认规则

- 按启动检查、初始化或恢复、提交执行、暂停或失败、结果判定、修复重启顺序阐述。
- 页面只显示当前状态，提供启动和暂停操作；后端独立校验状态。
- 同一时刻只允许一个迁移实例；启动使用数据库行锁和批次状态，不使用 Redis 锁。
- 首次初始化一次性保存完整任务；恢复保留原扫描范围和各任务进度。
- 任意任务失败均停止新处理、告警并由运维排查，不自动重试。
- 安全收尾后才允许恢复；完整任务全部成功后还需一致性校验。
