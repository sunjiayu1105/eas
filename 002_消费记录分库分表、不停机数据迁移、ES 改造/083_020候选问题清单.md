# 083_020候选问题清单

## 1 主问题　一般情况下，怎样确定 Java 线程池的核心线程数？

考点

1. 根据业务高峰期本池可用的 CPU 算力确定计算型任务的起始线程数。
2. 根据工作线程的阻塞等待时间与计算时间之比估算同步 I/O 任务的起始线程数。
3. 用代表性负载比较候选配置，选出满足吞吐和响应时间目标的较小档位。
4. 根据下游连接和处理能力判断继续增加线程是否还有收益。

答题范围

先给公式，再用同一份假设 CPU 预算对比两类任务。说明 N+1、2N 在什么条件下值得试测。结合生产高峰的请求组成、到达速率和持续时间解释如何压测。区分“在当前负载下达标”和“逐级加压后找到容量拐点”。队列策略作为控制条件，容量和扩容流程分别见现有 022、023。

候选理由

## 2 可选追问　如果高峰期队列持续增长，你会在什么情况下在线调大线程数？调完怎样判断要不要调回去？

考点

1. 根据 CPU 和下游利用情况判断排队是否可能通过增加线程缓解。
2. 结合核心线程数、最大线程数与队列策略说明什么时候增加的线程能够参与工作。
3. 根据完成速率、排队、尾延迟和拒绝数决定保留调整还是回退。

答题范围

主问题说明怎样定初始配置。此题承接运行中出现的持续积压，重点讲调整条件、效果验证和回退。配置中心可作为实现示例，项目是否采用需要实际依据。

候选理由
