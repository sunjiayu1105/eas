# 1. 概述
E账通系统的APP内消费、闪付交易、扫码付交易、快捷支付交易的介绍说明。

# 2. APP内消费交易
## 2.1 APP内消费概述
APP内消费，是广发作为收单方完成对一、二类户的账户消费交易的收单处理，并把汇总资金清算至商户对公户的金融服务。  
APP内消费的实施方案，由行外商户直连广发，调用广发APP接口完成交易。

## 2.2 业务流程描述
### 2.2.1 实时交易流程
## APP消费流程（文字版流程图）
泳道：APP/前置网关 → E账通 → 直销通 → 统一支付 → 核心

1. APP/前置网关：开始。
2. APP/前置网关：前端发起消费请求。
3. E账通：处理消费请求。
4. E账通：判断客户支付方式。支付方式包括：
    - 余额支付；
    - 绑定卡代收支付；
    - 授信支付；
    - 基金赎回支付。
5. 分支处理：
    - 余额支付：由E账通发起交易请求，核心处理资金结算，完成电子账户至消费过渡户的资金处理。
    - 绑定卡代收支付：调用统一支付/银联进行代收处理，核心完成代收垫资户、电子账户及消费过渡户之间的资金处理。
    - 授信支付：调用授信支付处理，核心完成授信垫资户、电子账户及消费过渡户之间的资金处理。
    - 基金赎回支付：完成基金赎回及消费资金处理，核心完成基金垫资户、电子账户及消费过渡户之间的资金处理。
6. 核心：处理交易请求，完成资金结算。
7. 核心 → E账通：返回处理结果。
8. E账通 → APP/前置网关：返回交易结果。
9. APP/前置网关：交易结束。

一、消费交易：

1. 商户前端对客户身份进行检查识别后，调用广发消费接口发起消费交易；
2. E账通处理消费请求：  
1）消费事中风控；  
2）消费校验，包括：订单流水号重复、交易金额校验、二类户限额校验、影像状态、各类黑白灰名单等；  
3）手续费预算，线上清算手续费的支付方式包括：0-消费类，1-理财类，02-UPOP卡代收消费类，03-UPOP卡代收理财类，4-基金消费类，5-基金理财类，6-授信额度消费类，17-余额+代扣支付；  
4）生成订单；  
5）按入参产品类型支付方式，完成支付交易；  
6）消费交易完成；
3. 消费交易完成，返回交易结果至商户。

二、撤销交易：

1. 商户前端调用广发接口，发起APP内消费的撤销请求；
2. E账通处理撤销请求：  
1）撤销交易初步校验，包括：校验金额、校验原订单、撤销退货交易赋值；  
2）退货手续费计算，按手续费规则比例计算退回手续费；  
3）校验撤销类型和金额，包括：校验全部和部分撤销、人寿积分计算、手续费计算；  
4）根据原订单支付方式，完成撤销处理；  
5）支持当天全部、部分撤销；
3. 撤销结果返回至前端。

三、退货交易：

1. 商户调用广发接口，发起APP内消费的退货请求；
2. E账通处理退货请求：  
1）退撤销退货初步校验，包括：校验金额、校验原订单、撤销退货交易赋值；  
2）退货手续费计算，按手续费规则比例计算退回手续费；  
3）校验退货类型和金额，包括：原订单金额；  
4）按原订单的支付方式完成退货交易；  
5）支持当天、隔天的全部、部分退货交易；
3. 交易结果返回至前端。

## 2.3 商户实例
一、人寿电商

人寿电商平台支持产险、寿险、养老、基金等理财产品交易，人寿电商平台调用广发APP内消费接口完成消费资金扣减，再与保险子公司确认业务交易。广发按业务日期清算汇总金额至人寿；

二、华为公交卡充值

泳道：公交侧 → 华为零钱 → 开放平台 → E账通 → 统一支付/银联 → 核心

1. 公交侧：开始。
2. 公交侧：客户发起公交卡充值请求，选择充值金额及支付方式，并提交至华为零钱。
3. 华为零钱：接收并处理充值请求。
4. 华为零钱：进行校验处理，包括：  
1）校验用户信息；  
2）校验账户及代扣信息；  
3）校验【无法识别】。
5. 公交侧：返回确认信息/充值请求结果【无法识别】。
6. 公交侧：发起支付请求。
7. 开放平台：处理支付请求，进行风控处理。
8. E账通：处理支付请求。
9. E账通：进行消费处理，包括：  
1）校验金额；  
2）校验交易订单；  
3）计算手续费。
10. E账通：判断支付方式。
11. 分支处理：
+ 若为本行账户/电子账户余额支付：核心完成账户余额至消费过渡户的资金处理。
+ 若为绑定卡代收/银联代收：统一支付/银联完成代收处理，核心完成代收垫资户、电子账户及消费过渡户之间的资金处理。
+ 若为【无法识别】支付方式：按对应资金链路完成处理。
12. 核心：完成资金处理后返回结果。
13. E账通/开放平台/华为零钱：逐级返回支付结果。
14. 公交侧：完成公交卡充值交易。

二、华为公交卡充值

1. 公交前端向华为发起充值校验请求，华为完成校验后进行加签，返回结果至公交前端；
2. 公交前端对支付请求再次进行加签处理，公交前端对接广发前置网关发起支付请求；
3. 前置网关进行两次验签处理，调用 E 账通接口发起支付请求；
4. E 账通处理支付请求：  
1）若请求账户属本行二、三类户，则校验账户信息；  
2）若请求账户属他行账户，则校验他行账户签约信息，不存在则拒绝交易；  
3）根据入参优惠规则编码和优惠类型判断逻辑如下：  
4）优惠类型包括：满减优惠、随机优惠，资金链路：对公户-应收网络款；  
5）根据入参产品类型处理支付请求；
5. 支付结果返回公交前端；
6. 公交发卡交易、收单交易结果，异步调用华为新增通知接口通知公交商户。

三、学费宝定时划扣

智慧幼儿园—划扣学费流程

泳道：E账通 → 核心

1. E账通：开始；
2. E账通：自动任务校验缴费协议，发起划扣学费请求；
3. E账通：请求部分解圈存；
4. 核心：处理活期余额部分解圈存；
5. E账通：发起并处理 APP 内消费交易，请求核心处理转账；
6. 核心：处理转账交易，资金链路：二类户-消费过渡户；
7. E账通：划扣交易结果；
8. 异步处理；
9. E账通：APP 内消费收单清算；
10. 核心：处理转账交易，资金链路：消费过渡户-对公户；
11. E账通：清算结果；
12. E账通：结束。
13. E账通自动任务，根据账户的年缴费定时划扣协议，调用核心 267510 账户解冻接口请求活期余额部分解圈存；
14. 提前零取交易成功后，进行 APP 内消费的余额支付，根据协议中学费信息完成支付交易，记录缴学费信息；
15. 第二天，由 APP 内消费清算自动任务完成收单清算至园区对公户。

# 3. 批量消费/退货交易
## 3.1 批量消费概述
人寿电商平台每日汇总当天需缴纳保费的客户名单、金额、产品代码、产品名称、对应专业公司等信息，调用慧理财批量消费接口，通过慧理财提交至 E 账通。E 账通实时受理批量交易请求，自动任务异步处理账户转账和虚账户台账扣减后，加入至隔天清算批次中完成清算。

## 3.2 业务流程描述
### 3.2.1 实时交易流程
#### 自动保费缴纳流程
泳道：人寿电商 → 网络理财服务系统 → E账通服务系统

1. 人寿电商：自动任务扫描需要交费的客户信息及商户信息记录；
2. 人寿电商：调用慧理财网络平台批量代收接口；
3. 网络理财服务系统：调用 E 账通批量代收接口；
4. E账通服务系统：接收请求，记录批次信息，校验信息，批量代收。

一、批量消费/退货流程

1. 人寿电商通过慧理财调用 E 账通批量消费/退货接口；

# 4. 闪付消费交易
## 4.1 闪付消费交易概述
闪付交易属银联非接触式支付产品，具备小额快速支付的特征。客户把我行账户加挂至各类手机 PAY、钱包 APP，用于超市、停车场、APP 平台消费等线上线下零售消费场所。闪付交易由银联转发至发卡行完成支付交易，由银联进行收单清算处理。

无跳转支付属银联商户网站内支付模式，持卡人在领航转第三方网关便可便捷完成支付。闪付交易包含无跳转支付交易。

## 4.2 业务流程描述
### 4.2.1 闪付加挂流程
一、手机 PAY 发起的加挂流程

#### 手机 PAY 发起的加挂流程（文字版流程图）
泳道：客户/手机 PAY → 商户 APP → 银联/卡交换 → 多应用 → E账通 → 核心/密码校验 → 银联/TSM → 手机 PAY

1. 客户在手机 PAY 或商户 APP 发起闪付加挂；
2. 免密加挂前端调用 YLJR126 获取闪付无感加挂验证码流水号；
3. 银联转发加挂请求至发卡行；
4. 卡交换转发加挂请求至多应用；
5. 多应用调用 E账通 FM8120 支付密码校验接口，请求校验密码；
6. E账通处理支付密码校验交易：  
1）查询账户信息；  
2）自营账户，按配置校验是否有做人脸识别，并请求核心验密；  
3）商户渠道请求入参密码字段为空，则进行免密加挂检查，校验账户归属渠道号与手机 PAY 厂商号的免密配置；  
4）商户渠道请求入参密码字段不为空，则请求商户前端进行验密，商户需采购加密机进行转加密；  
5）验密结果返回多应用；
7. 多应用向银联申请激活码；
8. 银联/TSM 返回写卡及加挂处理结果；
9. 手机 PAY 侧完成卡片加挂；
10. 加挂结果返回客户。
11. 客户在手机 PAY、商户 APP 进行闪付加挂，免密加挂前端需先调用 YLJR126 获取闪付无感加挂验证码流水号；
12. 银联转发加挂请求至发卡行，卡交换转发至多应用；
13. 多应用调用 E账通 FM8120-支付密码校验接口，请求校验密码；
14. E账通处理支付密码交易：  
1）查询账户信息；  
2）自营账户，按配置校验是否有做人脸识别，并请求核心验密；  
3）商户渠道请求入参密码字段为空，则进行免密加挂检查，校验账户归属渠道号与手机 PAY 厂商号的免密配置；  
4）商户渠道请求入参密码字段不为空，则请求商户前端进行验密，商户需采购加密机进行转加密；  
5）验密结果返回多应用；
15. 多应用向银联申请激活码，并加挂成功。

二、TSM 一键加挂

#### TSM 一键加挂流程（文字版流程图）
泳道：手机钱包/OPPO PAY → 发现精彩 APP → 银联/TSM → 发卡行/多应用 → 手机钱包

1. 客户进入手机钱包或 OPPO PAY 页面；
2. 客户选择“发现精彩”或进入“发现精彩一键绑卡”页面；
3. 手机钱包唤起发现精彩 APP；
4. 客户在发现精彩完成核身；
5. 客户选择绑定卡或选择加挂 OPPO PAY；
6. 发现精彩通过 TSM 控件请求银联完成写卡交易；
7. 银联/TSM 与发卡行完成卡片加挂、写卡处理；
8. 写卡成功后，银联分别通知 OPPO 和发现精彩；
9. 手机钱包页面展示卡片加挂结果。

一键绑卡入口一：客户在 OPPO PAY 页面选择发现精彩，OPPO 唤起发现精彩，客户在发现精彩完成核身并选择绑定卡，发现精彩通过 TSM 控件请求银联完成写卡交易，写卡成功由银联分别通知 OPPO、发现精彩；

一键绑卡入口二：客户在发现精彩一键绑卡页面，选择加挂 OPPO PAY，发现精彩通过 TSM 控件请求银联完成写卡交易，写卡成功由银联分别通知 OPPO、发现精彩。

### 4.2.2 无跳转支付认证流程
#### 无跳转支付认证流程（文字版流程图）
泳道：商户前端 → 银联/卡组织 → E账通 → 核心/密码校验

1. 商户前端发起无跳转支付账户验证请求；

1）校验是否允许对外鉴权；  
2）校验银联商户白名单；  
3）校验绑定卡、账户信息；  
4）存在密码则请求验密；  
5）验证结果返回前端；
4. 商户前端发起无跳转支付建立委托请求；
5. E账通处理建立委托：  
1）校验银联商户白名单；  
2）校验绑定卡、账户信息；  
3）存在密码则请求验密；  
4）验证结果返回前端。
6. 无跳转支付账户验证：  
1）校验是否允许对外鉴权；  
2）银联商户白名单；  
3）校验绑定卡、账户信息；  
4）存在密码则请求验密；  
5）验证结果返回前端。
7. 无跳转支付建立委托：  
1）银联商户白名单；  
2）校验绑定卡、账户信息；  
3）存在密码则请求验密；  
4）验证结果返回前端。

## 4.2.5 普通闪付消费
一、闪付消费

1. 银联转发闪付消费至发卡行处理，卡交换转发电子账户闪付消费请求至 E账通；
2. E账通处理闪付交易：  
1）闪付校验，包括：
    - 电子账户信息；
    - 账户黑灰名单：黑名单则拒绝交易，灰名单则拒绝交易并异步发送解冻短信；
    - 累计限额检查：二类户影像待审核校验累计消费限额；
    - 校验 MCC 黑名单：为防止信用卡套现，配置银联商户 MCC 号黑名单；
    - 校验终端标识黑名单：为防止信用卡套现，配置银联商户终端标识黑名单；
    - 校验有卡交易银联商户黑名单；
    - 校验无卡交易银联商户黑名单；
    - 区分扫码付和闪付交易；
    - 扫码付渠道限额、二类户日消费限额、三类户日消费限额；
    - 闪付交易 1000 元免密校验；  
2）事中风控；  
3）生成闪付订单，校验包括：
    - 查询支付方式；
    - 卡代收支付方式校验 MCC 黑名单、终端标识黑名单、有卡无卡交易黑名单；
    - 无跳转支付且信用卡代收支付，校验白名单进行交易；  
4）闪付验密；  
5）校验渠道是否使用消费红包，是则进入消费红包支付；  
6）按账户支付方式完成支付交易；  
7）处理日累计限额；
3. 返回交易结果至银联。

二、闪付消费冲正

1. E账通接收消费冲正请求，校验闪付交易信息，校验原订单信息，按原支付方式冲正交易；
2. 冲正失败：更新订单状态为强制成功，返回前端冲正成功。增加补退货流水，由业务室内管报表（内容“UPOP 差错处理报表”）手工发起退货；
3. 冲正异常：更新订单状态为闪付消费冲正异常，交由“闪付消费异常回查”批次任务发起回查。

三、闪付撤销

1. E账通处理闪付撤销请求，校验闪付交易信息，校验原订单信息，完成验密，按原支付方式撤销交易。

四、闪付撤销冲正

1. E账通处理闪付撤销冲正请求，校验闪付交易信息，校验原订单信息，完成验密，按原支付方式完成撤销冲正交易。

五、闪付退货

1. E账通处理闪付退货请求，校验闪付交易信息，校验原订单信息，完成验密，按原支付方式退货交易；
2. 退货失败：更新订单状态为退货失败，通过 E账通与 POS 对账后，业务至网银 R 内管“资金往来业务 > 电商移动支付 > 对账不平明细报表”，通过手工调账处理；
3. 退货异常：更新状态为异常，交由“银联全渠道退货”异常处理流程处理。

## <font style="background-color:#FBDE28;">4.2.7 闪付对账</font>
1. E账通获取核心交易文件、卡交换提供的银联文件完成对账；
2. 卡交换提供对账文件只包含正向未冲正的交易记录（消费成功、撤销成功、退货成功）；
3. E账通与核心对账，若存在差异提供监控报警，线下查明后处理，差异包括状态不一致（核心有 E账通无，T+2 日对账时 T 日 E账通有但核心对账文件中仍无）、金额不一致；
4. 对账处理：

| 交易类型 | 银联状态 | E账通状态 | 对账差异 | 对账处理 |
| --- | --- | --- | --- | --- |
| 消费 | 成功 | 成功 | 无 | 不处理 |
| 消费 | 失败 | 成功 | 银联无，广发有，进对账差异报表 | 按退货交易处理 |
| 撤销 | 成功 | 成功 | 无 | 不处理 |
| 撤销 | 失败 | 成功 | 银联无，广发有，进对账差异报表 | 按消费交易处理 |
| 退货 | 成功 | 成功 | 无 | 不处理 |
| 退货 | 成功 | 失败 | 银联有，广发无，进对账差异报表 | 按退货交易处理 |
| 退货 | 失败 | 成功 | 银联无，广发有，进对账差异报表 | 按消费交易处理 |

# 5. 扫码付交易
## 5.1 扫码付概述
银联二维码支付业务，使用支持银联二维码功能的 APP，通过商户或持卡人扫一扫功能，即可完成支付。基于银联二维码平台的扫码技术，实现“主扫”、“被扫”等扫码业务。

银联二维码支付接入模式区分：移动应用前置模式和银行卡前置模式。

移动应用前置模式：APP 网关无需通过银联转接即可完成支付，即行内扣款后通知银联，采用移动应用模式，该模式只有银行类 APP 适用。

银行卡前置模式：前端 APP 自行对接银联二维码平台获取支付信息，由银联转发交易请求至发卡行完成支付，该模式银行类 APP 和非银行 APP 都可以采用。

## 5.2 业务流程描述
### 5.2.1 直销银行扫码付
一、直销银行主扫业务

1. E账通处理二维码查询请求：  
1）校验影像信息；  
2）调用卡交换查询二维码信息；  
3）记录二维码信息；  
4）返回二维码信息至前端；
2. 直销 APP 查询二维码信息成功后，再调用 FM8209-二维码优惠查询，E账通请求卡交换查询优惠信息；
3. 直销 APP 展示支付订单信息，客户可选择支付方式进行支付；
4. 直销 APP 调用 FM8202-二维码消费接口发起消费请求；
5. E账通处理消费请求：  
1）风控校验；  
2）查询本地二维码订单信息；  
3）新增订单信息；  
4）查询客户信息；  
5）校验消费日累计限额，自营渠道超限则验密，人寿无需验密；  
6）按设置的支付方式进行支付，调用卡交换接口完成支付；  
7）累计日累计限额；
6. 返回消费支付结果至前端，并推送支付消息。

二、直销银行被扫业务

### 直销银行被扫业务流程（文字版流程图）
泳道：客户 → 直销 APP → 电子支付/移动前置 → E账通 → 卡交换 → 银联

1. 直销 APP 调用 E账通 FM8200-二维码申请接口，申请二维码；
2. E账通处理二维码申请：  
1）检查渠道生成二维码开关，开启则允许申请二维码；  
2）校验影像信息；  
3）查询客户信息；  
4）校验二、三类户消费额度；  
5）查询最高交易金额；  
6）查询免密金额；  
7）调用卡交换接口申请二维码；  
8）二维码申请成功，记录信息并返回结果至前端；
3. 商家扫描直销 APP 的二维码，并向银联发送消费支付请求；
4. 银联转发消费请求至发卡行，卡交换转发消费请求至 E账通；
5. E账通处理验密请求：  
1）查询二维码记录；  
2）判断是否超过限额；  
3）自营渠道通过消息中心推送验密请求和优惠信息，人寿渠道通过电子支付通知验密；
6. 客户在前端输入密码，调用 FM8216-二维码附加处理结果通知，E账通处理验密成功，并通知卡交换；
7. 卡交换发起被扫消费请求，调用 E账通 FM8207-二维码被扫接口处理消费请求；
8. E账通处理被扫消费请求：  
1）查询二维码申请记录；  
2）查询订单记录；  
3）查询客户信息；  
4）按账户支付方式处理卡代收请求、赎回请求；  
5）处理成功返回结果至卡交换；
9. 卡交换请求核心完成支付处理，支付结果调用 E账通 FM8208-二维码被扫消费结果推送接口，通知 E账通支付结果；
10. 卡交换返回支付结果至银联。

### 5.2.2 闪付的扫码付
一、闪付的扫码付主扫业务

### 二维码主扫消费流程（文字版流程图）
泳道：APP → 银联二维码平台 → 银联/卡交换 → E账通 → 直销通 → 统一支付 → 核心

1. 前端 APP 自行接入银联二维码平台，主扫商户二维码，并请求银联二维码平台获取订单信息；
2. 前端 APP 请求银联发起扫码付支付请求；
3. 银联转发支付请求至发卡行，卡交换转发消费请求至 E账通；
4. E账通处理流程参考 4.2 闪付业务流程描述；
5. 交易结果返回银联，银联返回商户前端。

二、闪付的扫码付被扫业务

### 二维码被扫消费流程（文字版流程图）
泳道：商户 → 客户 → 银联二维码平台 → 银联/卡交换 → E账通 → 直销通 → 统一支付 → 核心

1. 前端 APP 自行接入银联二维码平台，请求生成二维码；
2. 商家扫二维码并向银联发起消费请求；
3. 银联转发支付请求至发卡行，卡交换转发消费请求至 E账通；
4. E账通处理流程参考 4.2 闪付业务流程描述；
5. 交易结果返回银联，银联返回商户前端。

# 6. 快捷支付交易
## 6.1 快捷支付概述
快捷支付是指把账号加挂在商户 APP 上，通过第三方支付机构发起消费请求，通过银联或网联转发至发卡行处理消费支付交易；

## 6.2 业务流程描述
一、设置支付方式

1. 按渠道维度配置唯一支付方式，投产时脚本初始化配置渠道的快捷支付交易支付方式；
2. 按账户维度配置支付方式：  
1）投产时脚本初始化配置渠道支持的多种快捷支付交易支付方式；  
2）客户在商户前端界面选择支付方式；  
3）商户前端调用 E账通 FM8120 接口完成配置和查询；  
4）账户支付方式配置成功；

二、快捷支付的认证/签约

1. 系统链路：第三方支付机构-银联/网联-卡交换/统一支付-E账通-核心；
2. 客户在第三方支付机构 APP 加挂我行电子账户；
3. 银联/网联转发认证签约请求至发卡行，卡交换、统一支付转发请求至 E账通；
4. E账通处理 FM7700 快捷支付的认证签约信息：  
1）认证签约校验，包括：电子账户信息查询、公安认证、渠道准入权限、客户信息；  
2）身份认证处理，包括：自营渠道校验人脸识别，商户渠道校验是否免认证，商户渠道认证授权；  
3）返回认证结果至前端；
5. 身份认证成功返回结果至统一支付/卡交换，统一支付/卡交换记录标识并向客户手机号发送短信验证码；
6. 客户填写了短信验证码后提交签约，统一支付验证完短信验证码后再将交易发到 E账通进行签约校验；
7. E账通校验账号信息并返回结果给统一支付，加挂成功。

三、快捷支付的消费交易

1. 系统链路：第三方支付机构-银联/网联-卡交换/统一支付-E账通-核心；
2. 客户在前端发起快捷支付请求，第三方支付机构请求银联/网联；
3. 银联/网联转发消费请求至发卡行，卡交换、统一支付转发请求至 E账通；
4. E账通 FM7701 快捷支付处理消费请求：  
1）网联交易校验，包括：电子账户信息查询、账户黑灰名单校验、影像待审核限额累计校验、公安认证、获取渠道商户信息、影像信息；  
2）事中风控；  
3）按支付方式生成订单；  
4）按支付方式完成支付交易，若为授信垫资支付，则请求商户完成授信交易；  
5）累计消费限额；  
6）交易结果返回前端；
5. 交易结果返回前端。

四、快捷支付的消费冲正

1. 银联/网联判断消费交易超时，则发起消费冲正请求；
2. 卡交换、统一支付转发请求至 E账通；
3. E账通处理 FM7702-消费冲正：  
1）校验交易请求，渠道是否支持消费冲正交易类型；  
2）校验原订单信息，生成订单；  
3）按原订单支付方式处理消费冲正；  
4）冲正日累计限额累计；
4. 消费冲正结果返回前端。



四、快捷支付的消费冲正

3）按原订单支付方式处理消费冲正；  
4）冲正日累计限额累计；  
4. 消费冲正结果返回前端。

五、快捷支付的退货

1. 第三方支付公司发起退货请求；
2. E账通处理 FM7703-快捷支付退货交易：  
1）校验交易请求；

## 1.4. 优惠规则
1. 如果优惠金额不为 0，则消费交易开始前记录一条使用优惠流水 FM_DISCOUNT_RULE_FLOW，初始状态为 33，后面根据交易状态更新使用优惠流水状态。
2. FM_DISCOUNT_RULE_FLOW  
（1）FRDF_NUM（使用次数）  
① 消费交易，该字段记为 1  
② 撤销交易（需要恢复额度），该字段记为 -1  
③ 退货交易  
　1）部分退货（不需要恢复额度），该字段记为 0  
　2）全部退货（需要恢复额度），该字段记为 0
3. 单个用户的使用优惠限制规则（超限次数等）记录在 FM_FUND_GIFT_LIMIT。
4. 所有用户的使用优惠限制规则（超限次数、额度等）记录在 FM_FUND_GIFT_LIMIT。
5. 所有用户使用优惠次数、额度记录在 Redis 中。
6. 消费交易  
（1）根据 FM_DISCOUNT_RULE 配置的规则进行校验。  
（2）单个用户的超限次数记录在 FM_FUND_GIFT_LIMIT。如果有配置单个用户的使用优惠限制规则，则：  
① 查询每个用户的使用优惠流水记录，通过 SUM(FM_DISCOUNT_RULE_FLOW.FRDF_NUM) 计算每个用户总的使用次数。  
② 判断每个用户使用优惠的次数是否超限：  
　1）超限，校验不通过，交易结束；  
　2）未超限，继续流程。

（3）查询所有用户的优惠限制规则。如果不存在，则校验不通过；否则：  
① 判断所有用户使用优惠次数是否超限：  
　1）取出 Redis 中缓存的所有用户已使用次数 + 1，判断是否大于规则中配置的最大使用次数。  
　　a. 是，校验不通过，将 Redis 中的已使用次数 -1；  
　　b. 否，校验通过。

② 判断所有用户使用优惠额度是否超限：  
　1）取出 Redis 中缓存的所有用户已使用额度 + 本次优惠金额，判断是否大于规则中配置的最大使用限额。  
　　a. 是，校验不通过，将 Redis 中的已使用额度 - 本次优惠金额；  
　　b. 否，校验通过。

（4）以上校验通过，则新增一条使用优惠流水 FM_DISCOUNT_RULE_FLOW，初始状态为 33。  
（5）执行消费交易。  
（6）根据消费结果更新优惠使用次数、优惠额度。  
① 消费成功/异常：  
　1）更新所有用户使用优惠限制规则中的最大使用次数、最大额度 FM_FUND_GIFT_LIMIT。  
　　a. 剩余使用次数 -= 1；  
　　b. 剩余额度 -= 本地优惠金额。  
② 消费失败，需要恢复 Redis 中缓存的所有用户已使用次数、所有用户已使用额度。

7. 撤销交易  
（1）如果有使用优惠，则新增一条撤销使用优惠的流水，初始状态为 33。  
（2）执行撤销交易。  
（3）根据撤销交易结果，更新撤销使用优惠流水状态。  
（4）根据撤销结果，更新优惠已使用次数、已使用额度。  
① 撤销成功，需要恢复已使用次数、已使用额度：  
　1）恢复 Redis 中缓存的所有用户已使用次数、所有用户已使用额度；  
　2）更新所有用户使用优惠限制规则中的剩余使用次数、剩余最大额度 FM_FUND_GIFT_LIMIT。  
　　a. 剩余使用次数 += 1；  
　　b. 剩余额度 += 本地优惠金额。  
② 撤销失败/异常，无需其他操作。
8. 退货交易  
（1）如果有使用优惠，则新增一条撤销使用优惠的流水，初始状态为 33。  
（2）执行退货交易。  
（3）根据退货交易结果，更新优惠退货流水状态。  
（4）如果正交易有使用优惠，退货成功后需要更新额度，退货失败或异常无需更新额度。  
① 恢复 Redis 中缓存的所有用户已使用次数、所有用户已使用额度；  
② 更新所有用户使用优惠限制规则中的最大使用次数、最大额度 FM_FUND_GIFT_LIMIT。  
　1）剩余使用次数 += 1；  
　2）剩余额度 += 本地优惠金额。

（1）待处理/生成文件失败。

　　④ 生成 end 文件。
