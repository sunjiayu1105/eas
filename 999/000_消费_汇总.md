# 二、《消费业务_A梳理后_1》内容梳理
## 1. 概述
本文档主要说明 E账通系统中的消费类交易能力，覆盖：

1. APP 内消费；
2. 批量消费/退货；
3. 闪付消费；
4. 扫码付交易；
5. 快捷支付交易；
6. 对账、清算、批次任务；
7. 商户接入场景；
8. 接口清单和后台任务清单。

---

## 2. APP 内消费交易
### 2.1 APP 内消费概述
APP 内消费是指用户在合作方 APP 中完成支付，E账通处理支付、扣款、优惠、清算、回查等逻辑。

常见链路：

商户 APP / 前置网关  
→ E账通  
→ 直销银行/统一支付/核心  
→ 返回交易结果

---

### 2.2 业务流程描述
#### 2.2.1 实时交易流程
APP 内消费主要包括：

1. APP 消费；
2. 消费交易完成；
3. 撤销交易；
4. 退货交易。

---

### 2.3 APP 消费流程
主要流程：

1. 商户前端发起 APP 内消费请求；
2. E账通接收并处理请求；
3. 根据产品类型、账户类型、支付方式判断资金链路；
4. 校验账户、商户、订单、限额、优惠等信息；
5. 按支付方式完成支付；
6. 记录交易流水；
7. 返回交易结果；
8. 后续可进入撤销、退货、回查、对账等流程。

---

### 2.4 消费交易完成
消费成功后：

1. 更新交易状态；
2. 更新交易明细；
3. 记录流水；
4. 根据业务场景更新商户账户或对公账户；
5. 对涉及优惠的交易，更新优惠使用次数、额度；
6. 后续进入清算、对账或订单结果通知。

---

### 2.5 撤销交易
撤销用于消费交易后的冲正或取消。

处理要点：

1. 查询原交易；
2. 判断原交易状态；
3. 判断是否可撤销；
4. 执行撤销交易；
5. 如果消费时使用优惠，撤销成功后需要恢复优惠次数和额度；
6. 更新原交易和撤销交易状态；
7. 返回撤销结果。

---

### 2.6 退货交易
退货用于消费完成后的退款。

处理要点：

1. 查询原交易；
2. 判断是否可退货；
3. 支持部分退货、全部退货；
4. 可支持多次退货；
5. 计算剩余可退金额；
6. 根据支付金额、代扣金额、积分金额、优惠金额等顺序进行退货金额拆分；
7. 更新交易明细、退货流水和优惠流水；
8. 返回退货结果。

# 四、闪付消费交易
## 1. 闪付消费概述
闪付消费主要包括：

1. 手机 PAY 加挂；
2. TSM 一键加挂；
3. 无跳转支付认证；
4. 支付方式设置；
5. 京东白条闪付消费；
6. 闪付消费、撤销、退货；
7. 对账；
8. 批次任务。

---

## 2. 手机 PAY 发起加挂流程
主要流程：

1. 用户在手机 PAY 前端发起加挂；
2. APP 请求开放平台；
3. 开放平台请求 E账通；
4. E账通处理账户、客户、短信、影像等信息；
5. 调用统一支付/银联/TSM 等系统；
6. 完成卡片加挂；
7. 返回加挂结果。

---

## 3. TSM 一键加挂流程
主要流程：

1. 用户进入手机钱包或 OPPO PAY 等入口；
2. 选择发卡行；
3. 发起加挂；
4. 调用 TSM；
5. 验证用户信息；
6. 生成或绑定卡片；
7. 返回加挂结果。

---

## 4. 无跳转支付认证流程
主要处理：

1. 商户发起无跳转支付申请；
2. E账通校验客户、账户、商户信息；
3. 校验渠道授权；
4. 校验签约信息；
5. 返回认证结果。

---

## 5. 支付方式配置
支付方式配置包括：

1. 余额支付；
2. 绑定卡支付；
3. 基金支付；
4. 授信支付；
5. 组合支付。

配置规则：

1. 按渠道维度配置唯一支付方式；
2. 投产时按初始化配置同步；
3. 查询接口用于读取当前支付方式；
4. 修改接口用于变更支付方式。

---

## 6. 京东白条闪付消费
### 6.1 京东白条闪付消费流程
1. 商户前端发起闪付消费请求；
2. E账通接收请求；
3. 校验账户、商户、交易信息；
4. 调用核心或相关支付系统；
5. 执行支付；
6. 返回支付结果。

### 6.2 京东白条撤销、退货
1. 查询原交易；
2. 校验是否支持撤销或退货；
3. 调用对应接口；
4. 更新交易状态；
5. 返回结果。

---

5. 生成差异报表；

# 六、快捷支付交易
## 1. 快捷支付概述
快捷支付是指账户加挂到第三方支付机构 APP 后，通过银联、网联、卡交换、统一支付、E账通、核心完成支付。

---

## 2. 设置支付方式
主要流程：

1. 按渠道维度配置唯一支付方式；
2. 投产时初始化配置；
3. 商户前端调用 E账通接口完成配置和查询；
4. 账户支付方式配置成功。

---

## 3. 快捷支付认证/签约
链路：

第三方支付机构  
→ 银联/网联  
→ 卡交换/统一支付  
→ E账通  
→ 核心

主要流程：

1. 客户在第三方支付机构 APP 加挂我行电子账户；
2. 银联/网联转发认证签约请求；
3. 统一支付/卡交换转发至 E账通；
4. E账通处理 FM7700 快捷支付认证签约；
5. 校验电子账户、公安认证、渠道准入、客户信息；
6. 身份认证成功后发送短信验证码；
7. 客户提交短信验证码；
8. E账通校验并返回签约结果；
9. 加挂成功。

---

## 4. 快捷支付消费交易
主要流程：

1. 客户在第三方支付机构发起快捷支付；
2. 第三方支付机构请求银联/网联；
3. 银联/网联转发至发卡行；
4. 统一支付/卡交换转发至 E账通；
5. E账通处理 FM7701 快捷支付；
6. 校验账户、黑灰名单、影像审核限额、公安认证、渠道商户信息；

## 5. 优惠规则
### 5.1 基础规则
1. 优惠金额不为 0 时，消费交易开始前记录优惠流水：
    - 表：`FM_DISCOUNT_RULE_FLOW`
    - 初始状态：33
2. `FRDF_NUM` 规则：

| 场景 | FRDF_NUM |
| --- | --- |
| 消费交易 | 1 |
| 撤销交易，需要恢复额度 | -1 |
| 部分退货，不需要恢复额度 | 0 |
| 全部退货，需要恢复额度 | 0 |


3. 单个用户优惠限制规则记录在：
    - `FM_FUND_GIFT_LIMIT`
4. 所有用户优惠限制规则也记录在：
    - `FM_FUND_GIFT_LIMIT`
5. 所有用户使用次数和额度记录在 Redis 中。

---

### 5.2 消费优惠校验逻辑
#### 根据 `FM_DISCOUNT_RULE` 校验
1. 判断优惠规则是否存在；
2. 判断当前系统时间是否在优惠规则时间范围内；
3. 判断实际交易金额是否满足最小交易金额；
4. 判断优惠类型。

#### 随机优惠
1. 如果实际交易金额小于随机优惠最大金额，则应将随机优惠最大金额调整为实际交易金额；
2. 根据随机优惠最小金额和最大金额生成优惠金额；
3. 计算 `payAmt = 订单金额 - 优惠金额`；
4. 文档提出：还需要比较实际交易金额与随机优惠最小金额，否则可能出现随机金额不合理。

#### 满减优惠
1. 判断第三方上送优惠金额是否与规则配置一致；
2. 一致则通过；
3. 不一致则不通过。

#### 单个用户限制
1. 查询 `FM_FUND_GIFT_LIMIT`，`FFGL_LIMIT_TYPE='5'`；
2. 不存在则继续；
3. 存在则查询 `FM_DISCOUNT_RULE_FLOW` 获取用户使用次数；
4. 判断是否超限；
5. 文档提出：这里可能存在并发问题。

#### 所有用户限制
1. 查询所有用户配置；
2. 判断时间范围；
3. Redis 中累计使用次数 +1，判断是否超过最大次数；
4. Redis 中累计使用额度 + 本次优惠金额，判断是否超过最大额度；
5. 超限则回滚 Redis 计数或额度。

---

## 6. 优惠使用后的额度处理
### 消费成功/异常
1. 更新所有用户最大使用次数、最大额度；
2. 剩余次数 -= 1；
3. 剩余额度 -= 本地优惠金额。

### 消费失败
恢复 Redis 中：

1. 所有用户已使用次数；
2. 所有用户已使用额度。

### 撤销成功
1. 恢复 Redis 已使用次数和额度；
2. 更新 `FM_FUND_GIFT_LIMIT`：
    - 剩余次数 += 1；
    - 剩余额度 += 本地优惠金额。

### 撤销失败/异常
无需处理。

### 退货成功
1. 恢复 Redis 已使用次数和额度；
2. 更新 `FM_FUND_GIFT_LIMIT`：
    - 剩余次数 += 1；
    - 剩余额度 += 本地优惠金额。

### 退货失败/异常
无需更新额度。

## 12. FM2437 消费支付退货
### 重点
1. 恢复优惠次数；
2. 恢复优惠额度。

### 功能
1. 支持对公户支付、账户支付、对公户 + 账户支付退货；
2. 支持隔天处理；
3. 支持部分退货、全部退货、多次退货；
4. 退货成功恢复额度。

### 退货金额计算
退货扣款优先级：

1. 剩余支付金额 `payAmt`；
2. 剩余代扣金额 `collectionAmt`；
3. 剩余积分金额 `freeAmt`；
4. 剩余优惠金额 `discountAmount`。

判断逻辑：

1. 是否存在原交易；
2. 退货金额是否与交易金额一致；
3. 是否存在撤销且状态为 90 或 33 的交易；
4. 查询原订单金额；
5. 查询已退货金额；
6. 计算剩余可退金额；
7. 判断退货金额是否大于剩余交易金额；
8. 依次扣减 payAmt、collectionAmt、freeAmt、discountAmount；
9. 若退货金额超过可退总额，则退货失败。

### APP 消费退货
接口：

`FM: NewAppConsume | AppConsumeReturn`

行内/行外均需判断 productType：

1. productType=19：
    - 无优惠：余额退货；
    - 有优惠：组合支付退货，payAmt 退回电子账户，discountAmt 退回我行对公户。
2. productType=20：
    - 对公红包退货；
    - discountAmt：商户对公户 → 我行对公户。
3. productType=21：
    - payAmt：商户对公户 → 电子账户 → 绑定卡；
    - discountAmt：商户对公户 → 我行对公户。
4. productType=0：
    - 余额退货。

1. 同步更新总额度、剩余总额度；
2. 同步更新总笔数、剩余总笔数。

文档提出问题：

1. 代码似乎直接修改，没有校验；
2. 如果总笔数从 100 改为 50，但已使用 80，则不合理；
3. 可能原设计是脚本配置，不允许内管修改；
4. 如改成可修改，需要考虑：
    - 已使用次数与新总次数；
    - 已使用额度与新总额度；
    - 并发问题；
    - 修改时是否允许正在交易。

## 3. 开户与账户生命周期
## 3.1 开户：FM1110
开户支持两种模式：

1. 开二类户 + 三类户；
2. 只开三类户。

### 开二类户 + 三类户流程
1. 前端上传身份证件信息、影像信息、账户信息、短信验证码；
2. E账通先处理二类户开户；
3. 二类户开户成功后，再开立影子三类户；
4. 二类户开户失败，则不继续开影子三类户；
5. 影子三类户开户失败，则接口返回交易失败；
6. 从 II 类户绑定卡充值 0.01 元至三类户；
7. 影子三类户不保留资金，通过动账机制自动处理；
8. 影子三类户开户成功后，同步处理影子三类户绑定钱包二类户。

### 只开三类户流程
1. 使用钱包二类户卡号进行开户校验；
2. 三类户开户成功后，同步发起影子卡代收交易；
3. 从 II 类户绑定卡充值 0.01 元至三类户；
4. 充值金额保留在钱包三类户。

### 开户补充规则
1. 红包渠道不校验短信验证码；
2. 短信验证码校验后再进行实名信息核验；
3. HW1001 开户接口调用异步机制；
4. 红包内的通用开户请求不计入次数；
5. 最终开户结果通过前端回查接口返回。

---

## 3.2 三类户升级二类户：HW0005
### 功能
三类户升级为二类户。

### 流程
1. 三类户升级为二类户；
2. 同时开立影子三类户；
3. 影子三类户绑定二类户；
4. 影子三类户充值。

### 升级规则
1. 客户在该渠道已存在 II 类户，则升级失败；
2. 客户未上传影像信息，则升级失败；
3. 当前有效且绑定的 II 类户中第三方绑定账户必须为 I 类户；
4. 仅支持三类户升级二类户；
5. 三类户升级二类户后，电子账户号不变；
6. HW0005 采用异步机制，前端通过回查接口查询最终结果。

---

## 3.3 绑卡：HW1005
功能：

用户使用银行卡建立账户绑定关系。

流程：

2. 校验三类户的当前绑定卡签约关系；
3. 绑定关系调用交易账户类能力；
4. 绑定成功后返回结果；
5. 绑卡失败不重复发起绑卡请求，返回失败结果。

功能：

用户解除银行卡绑定关系。

流程：

3. 校验账户是否允许解绑；

# 十二、扫码付与无跳转支付
## 1. 扫码付主扫消费
链路：

APP  
→ 银联二维码平台  
→ 银联/卡交换  
→ E账通  
→ 核心

流程：

1. 用户扫描商户二维码；
2. 前端调用二维码平台查询订单；
3. APP 展示订单信息；
4. 用户确认订单；
5. 前端调用扫码收款接口发起主扫消费；
6. E账通校验交易信息；
7. 卡交换转发至 E账通；
8. E账通按渠道支付方式完成支付；
9. 核心处理借记；
10. 返回结果。

---

## 2. 扫码付被扫消费
流程：

1. 前端申请二维码；
2. 收单商户扫描二维码；
3. 银联判断交易属于天府通 APP；
4. 银联通知前端；
5. 前端确认订单并发起支付；
6. E账通完成支付；
7. 核心完成资金处理；
8. 返回交易结果。

---

## 3. 无跳转支付
流程：

1. APP 发起消费请求；
2. 银联/卡交换识别商户电子账户交易；
3. 请求转发至 E账通；
4. E账通校验商户和账户；
5. 若为白名单商户则交易成功；
6. 不在白名单则交易失败；
7. 按商户配置支付方式处理；
8. 核心扣款；
9. 返回交易结果。

规则：

1. 天府通无跳转支付默认余额支付；
2. 无跳转支付白名单由业务提供；
3. 核心扣账失败则交易失败；
4. 核心扣账超时，E账通发起冲正。

---

# 十四、APP 内消费、撤销与退货
## 1. APP 内消费：FM2301

6. 超额则交易失败；
7. 未超额则按原支付方式退货。

# 十八、异常处理归纳
## 1. 异步交易回查
以下交易可同步机制或异步机制确认最终状态：

1. 开户；
2. 三类户升级；
3. 充值；
4. 提现；
5. APP 内消费；
6. APP 内消费撤销；
7. APP 内退货。

---

## 2. 可回查接口
| 场景 | 回查接口 |
| --- | --- |
| 开户、升级 | HW1004 |
| 充值、提现 | FM1103 |
| APP 内消费、撤销、退货 | FM2305 |
| 账户余额 | FM1017 |
| 交易列表 | FM9101 |
| 交易明细 | FM9102 |


---

## 3. 失败处理规则
1. 二类户开户失败，不继续开影子三类户；
2. 影子三类户开户失败，接口返回交易失败；
3. 代收失败，不重发代收请求；
4. 影子三类户绑卡失败，不重发绑卡请求；
5. 影子三类户解绑失败，由业务内管手工处理；
6. 核心扣账失败，直接返回交易失败；
7. 核心扣账超时，发起冲正；
8. 消费交易异常可通过回查接口查询最终状态。
