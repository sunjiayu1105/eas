两个 Java 实例同时处理同一个订单时，各自的本地锁存在各自的进程里。实例 A 拿到自己的锁，实例 B 仍能拿到它自己的锁，两边都可能处理同一订单。如果业务需要协调这些请求，就让所有实例连接同一套 Redis，竞争订单对应的同一个锁键。只有明确拿到锁的请求才进入受保护的业务。[详细说明（第 26 行）](<D:/000/sources/eas/000_Redis/003_为什么多实例部署时Java本地锁不够用.md:26>)

## 5 详细方案

### 5.1 本地锁的作用范围

同一个 JVM 内，线程需要使用同一个锁对象才能互斥。不同 JVM 中即使用同一段代码和同一个订单号，也会分别持有自己的锁对象。共享锁的前提是所有业务入口遵守同一套锁键规则，并依据获取结果决定是否执行。锁失效仍可能导致并发，见 [006 Redis锁失效后为什么旧请求还能写入](<D:/000/sources/eas/000_Redis/006_Redis锁失效后为什么旧请求还能写入.md>)。
