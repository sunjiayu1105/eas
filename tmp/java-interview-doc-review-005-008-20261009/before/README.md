## 文档维护与已确认规则

- Canal Server 部署方式按用户确认与参考文章的单机方案保持一致：1 台主机上的 1 个 Server 进程承载 db0、db1 两个 destination，不接入 ZooKeeper，不配置自动主备切换。
- 当前选用 file-instance.xml 本地位点模板，两个通道各自维护持久化进度；故障后人工核对本地位点和日志连续性，再重启恢复。单机进程故障会同时中断两个通道的采集和发布，位点丢失或日志断档时暂停复核，不能跳到最新 GTID。
- 该调整只涉及 Canal Server 部署和恢复方式；两个独立 MySQL 实例、技术栈版本、原生 RocketMQ 链路及 MQ/ES 各阶段确认规则沿用当前项目基线，实际本地落盘与恢复仍待验证。
- 005～008 按各自职责组织口述和详细方案；整体概括与分点对应，跨组件内容只保留交接和必要边界，实现细节在负责该环节的文档展开。顺序控制沿用 007、008 的 binlog 来源位置规则，不在消费记录表新增版本号字段，相关实现仍待验证。
