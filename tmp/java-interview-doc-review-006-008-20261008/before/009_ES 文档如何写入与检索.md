# 3.4.1.4 ES 如何定位、写入和检索文档？

以下内容按照当前项目 `AGENTS.md` 项目级规则中规定的技术栈版本为准。

## 文档维护与已确认规则

- 当前由自定义 MQ 消费服务写入 ES，不再采用 008 的旧 Adapter SQL 映射。
- consumeId 同时用于 `_id` 和普通排序字段；稳定 `_id` 只保证同一物理索引内唯一，历史更新删除与 INSERT 重放须沿用原索引。
- 路由预留、来源顺序、删除标记和字段转换仍是待实现验证的机制，不表述为已上线能力。

## 面试口述精炼版本

**用索引和 `_id` 定位文档**：本方案用新表 `consumeId` 作为 ES `_id`（具体索引内的文档标识）。同一索引同一时刻不能存两篇相同 `_id` 的文档；重复提交是替换还是冲突，取决于 `index`、`create` 等具体操作。物理删除需找到原具体索引；详见[009_ES 文档如何写入与检索.md](<D:/000/sources/eas/002_消费记录分库分表、双写与ES 改造（15）/009_ES 文档如何写入与检索.md:6>)。

**写入成功后仍要等待搜索可见**：ES 按 Mapping 处理写入并返回结果；相关分片 refresh 后新状态才对搜索可见。ES 响应既不负责 Canal 消费确认，也不能替代新表与 ES 的独立数据比较。

## 详细方案

**以具体索引和 `_id` 定位文档**

`_id` 是 ES 在具体索引内唯一标识文档的元数据，用于按 ID 获取、写入、更新和删除。本方案用新表 `consumeId` 的值作 `_id`；它与 `_source` 中的业务字段 `consumeId` 不是同一字段，项目要求自定义服务显式写入两者，使其表达同一业务标识。`_id` 不能跨 rollover 索引全局定位。同一具体索引内同一时刻不能有两篇不同文档共用 `_id`，但重复提交是否报错取决于请求类型。

**字段转换：** 008 的自定义服务从行事件提取主键设置 `_id`，同时把 consumeId 作为普通字段写入文档，不需要新增 esDocId Mapping 字段或生成 32 份 Adapter 映射。真实新表列名、字段类型、时间和金额转换仍需对齐；验收检查 `_id` 与 `_source.consumeId` 一致，不把设计要求写成已完成事实。

**按请求类型处理重复 ID**

`index` 写入完整文档，不存在则创建，存在则替换，不因重复 `_id` 报错；`create` 只在不存在时创建，重复时返回 `409` 冲突。Index API 的 `op_type=create` 与 `create` 语义相同，Bulk 请求则使用 `create` 操作。`update` 更新已有文档，不存在时在未配置 upsert 的情况下通常返回 `404`；`delete` 删除对应文档，不存在时通常返回未找到结果。`_bulk` 整体请求可能返回 `200`，但单项仍可能失败，须检查每项结果。

**按 Mapping 写入，refresh 后提供搜索**

**当前请求对应关系：** 首次 INSERT 先可靠预留物理索引，再按幂等规则选择 Index 或 Create；UPDATE 先定位原索引，选择局部 Update 或完整覆盖；DELETE 对原索引执行删除，并保留删除后的来源顺序。具体请求选择仍待实现验证，不能把旧 Adapter 的默认 upsert 和回查行为当成当前自定义服务配置。详见 008。

**缺字段与 Upsert 边界：** 局部 Update 只修改提交的字段，不会自动补齐历史缺字段；开启 upsert 可能以不完整字段创建缺失文档，也不能解决跨索引定位。是否需要修复历史字段须先检查真实文档和完整字段契约，本次不把历史问题或补数结果写成已验证事实。

ES 按目标具体索引的 Mapping 检查字段、保存文档并建立查询结构。当前 Mapping 设计为 `dynamic: "strict"`，未声明字段会导致对应写入失败；现有 17 字段不能视作新表全字段。成功写入或删除不等于立即搜索可见，相关分片 refresh 后变更才对搜索可见。字段契约和查询约束见[012_ES Mapping 设计.md](<D:/000/sources/eas/002_消费记录分库分表、双写与ES 改造（15）/012_ES Mapping 设计.md:5>)。

**rollover 后定位原索引**

本方案采用 rollover：每 30 天切换当前写索引，索引在 rollover 后 180 天进入 Cold 阶段。写别名只将写入路由到当前写索引，不会自动查找历史索引里的相同 `_id`。因此新增重试、历史文档更新与物理删除，须可靠确定原具体索引并检查跨索引重复。现有部署模板仍没有完整的定位和重放实现，不能据此认定 rollover 同步已可上线；生产边界见[016_ES 生产环境部署架构.md](<D:/000/sources/eas/002_消费记录分库分表、双写与ES 改造（15）/016_ES 生产环境部署架构.md:6>)。
