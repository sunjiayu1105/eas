# 3.4.1.4 ES 如何定位、写入和检索文档？

以下内容按照当前项目 `AGENTS.md` 项目级规则中规定的技术栈版本为准。

## 面试口述精炼版本

**用索引和 `_id` 定位文档**：本方案用新表 `consumeId` 作为 ES `_id`（具体索引内的文档标识）。同一索引同一时刻不能存两篇相同 `_id` 的文档；重复提交是替换还是冲突，取决于 `index`、`create` 等具体操作。物理删除需找到原具体索引；详见[009_ES 文档如何写入与检索.md](<D:/000_ 找工作_2026/sources/E账通/002_消费记录分库分表、双写与ES 改造（15）/009_ES 文档如何写入与检索.md:18>)。

**写入成功后仍要等待搜索可见**：ES 按 Mapping 处理写入并返回结果；相关分片 refresh 后新状态才对搜索可见。ES 响应既不负责 Canal 消费确认，也不能替代新表与 ES 的独立数据比较。

## 详细方案

**以具体索引和 `_id` 定位文档**

`_id` 是 ES 在具体索引内唯一标识文档的元数据，用于按 ID 获取、写入、更新和删除。本方案用新表 `consumeId` 的值作 `_id`；它与 `_source` 中的业务字段 `consumeId` 不是同一字段，项目要求两者表达相同业务标识，不能假定 Adapter 自动复制。`_id` 也不能跨 rollover 索引全局定位。同一具体索引内同一时刻不能有两篇不同文档共用 `_id`，但重复提交是否报错取决于请求类型。

**映射调整与来源：** 008 的建议模板改为 `_id: esDocId`，SQL 分别声明 `consume_id AS esDocId` 和 `consume_id AS consumeId`，前者提取元数据 ID，后者提供普通文档字段；业务主键值不变。[Canal 1.1.7 ES7xTemplate.java](https://github.com/alibaba/canal/blob/canal-1.1.7/client-adapter/es7x/src/main/java/com/alibaba/otter/canal/client/adapter/es7x/support/ES7xTemplate.java)的字段转换方法会排除配置为 `_id` 的别名对应的普通字段，因此不能继续依赖旧示例自动保留 consumeId。双别名解析、增量转换、回查与实际写入仍待验证；需检查 `_id` 与 `_source.consumeId` 的业务标识一致，不将设计要求描述为已写入事实。

**按请求类型处理重复 ID**

`index` 写入完整文档，不存在则创建，存在则替换，不因重复 `_id` 报错；`create` 只在不存在时创建，重复时返回 `409` 冲突。Index API 的 `op_type=create` 与 `create` 语义相同，Bulk 请求则使用 `create` 操作。`update` 更新已有文档，不存在时在未配置 upsert 的情况下通常返回 `404`；`delete` 删除对应文档，不存在时通常返回未找到结果。`_bulk` 整体请求可能返回 `200`，但单项仍可能失败，须检查每项结果。

**按 Mapping 写入，refresh 后提供搜索**

**当前 Adapter 请求对应关系：** 008 的单表简单字段映射在配置 `_id`、保持默认 `upsert=false` 时，将 INSERT 转为 Index 请求、UPDATE 转为按变化字段提交的局部 Update、DELETE 转为按事件 ID 删除的请求；该分支直接使用事件数据，不要求每次回查 MySQL。依据：[Canal 1.1.7 ESSyncConfig.java](https://github.com/alibaba/canal/blob/canal-1.1.7/client-adapter/escore/src/main/java/com/alibaba/otter/canal/client/adapter/es/core/config/ESSyncConfig.java)、[ESSyncService.java](https://github.com/alibaba/canal/blob/canal-1.1.7/client-adapter/escore/src/main/java/com/alibaba/otter/canal/client/adapter/es/core/service/ESSyncService.java)及 [ES7xTemplate.java](https://github.com/alibaba/canal/blob/canal-1.1.7/client-adapter/es7x/src/main/java/com/alibaba/otter/canal/client/adapter/es7x/support/ES7xTemplate.java)。复杂映射另有回查分支，不能将这些结论泛化到所有配置。

**缺字段与 Upsert 边界：** 双别名映射旨在为后续正确生成的文档同时提供 `_id` 和 consumeId，不自动修复历史文档。如果已有文档缺少 consumeId，而 UPDATE 中 consume_id 未变化，局部更新通常不会补入该字段。本文保持默认 upsert=false，不用开启 Upsert 代替补数：局部字段在目标文档不存在时可能被用来创建不完整文档，也无法解决原索引定位。以上是源码推导的条件性风险，并非生产问题或修复结果的实测结论；本次不新增补数方案，双别名解析及增删改行为仍待联调。

ES 按目标具体索引的 Mapping 检查字段、保存文档并建立查询结构。当前 Mapping 设计为 `dynamic: "strict"`，未声明字段会导致对应写入失败；现有 17 字段不能视作新表全字段。成功写入或删除不等于立即搜索可见，相关分片 refresh 后变更才对搜索可见。字段契约和查询约束见[012_ES Mapping 设计.md](<D:/000_ 找工作_2026/sources/E账通/002_消费记录分库分表、双写与ES 改造（15）/012_ES Mapping 设计.md:5>)。

**rollover 后定位原索引**

本方案采用 rollover：每 30 天切换当前写索引，索引在 rollover 后 180 天进入 Cold 阶段。写别名只将写入路由到当前写索引，不会自动查找历史索引里的相同 `_id`。因此新增重试、历史文档更新与物理删除，须可靠确定原具体索引并检查跨索引重复。现有部署模板仍没有完整的定位和重放实现，不能据此认定 rollover 同步已可上线；生产边界见[016_ES 生产环境部署架构.md](<D:/000_ 找工作_2026/sources/E账通/002_消费记录分库分表、双写与ES 改造（15）/016_ES 生产环境部署架构.md:31>)。
