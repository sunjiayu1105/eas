# 一、账户类型
## 1. 个人银行账户分类
个人银行账户分为：

1. 一类户
2. 二类户
3. 三类户

其中，网点柜面开户属于面签账户，需要提交身份证明资料原件、本人签名。  
通过电子渠道开立、无实体卡的银行账户属于非面签账户，也就是 E 账通渠道开立的电子账户。

## 2. 一类户
一类户特点：

1. 没有限额控制。
2. 没有交易场景控制。
3. 支持现金交易。

## 3. 二类户
### 3.1 面签二类户
1. 消费 / 转账限额：日累计 1 万元，年累计 20 万元。
2. 支持现金交易。

### 3.2 非面签二类户
1. 开户必须用一类户作为绑定卡。
2. 需要上传身份证影像。
3. 需要上送 9 要素。
4. 只能通过绑定卡出入金。
5. 消费限额：日累计 1 万元，年累计 20 万元。
6. 不支持现金交易。

## 4. 三类户
### 4.1 面签三类户
1. 时点余额不超过 2000 元。

### 4.2 非面签三类户
1. 开户需要绑定卡。
2. 可绑定一类户、二类户、三类户，具体看 E 账通渠道配置。
3. 可以非绑定入金，需要单独配置，通过调用非绑定入金接口设置。
4. 时点余额不超过 2000 元。
5. 消费限额：日累计 2000 元，年累计 5 万元。
6. 所有三类户累计双边超过 5 万元，必须上传影像。

## 5. 数量限制
1. 同一客户在同一银行最多开 1 个一类户。
2. 同一客户在同一银行最多开 5 个二类户。
3. 同一客户在同一银行最多开 5 个三类户。

# 二、OCR 基础概念
OCR：Optical Character Recognition，即文字识别。

文件中涉及 OCR 的主要场景是：

1. 识别身份证影像内容。
2. 校验证件影像是否正确。
3. 校验 OCR 识别结果与客户上送信息是否一致。
4. 为开户、影像审核、客户信息建档等流程提供基础数据。

# 三、二类户 / 三类户开户
## 1. 涉及接口
1. FM1100
2. FM0027
3. FM3327

## 2. 重点
同一大渠道、同一用户不能同时开多个账户。

## 3. 代码清单
1. FM0027
2. FM3327

## 4. 二类户 + 三类户开户流程
### 4.1 用户 / 前置网关
1. 上传身份证影像。
2. 填写开户信息。
3. 发起开户。

### 4.2 E 账通处理
1. OCR 审核子流程。
2. 开户基础校验，包括：
    - 年龄是否 ≥ 16 周岁；
    - 是否开户黑名单；
    - 是否非法卡 BIN；
    - 是否人脸识别通过，按渠道判断；
    - 手机号是否已被其他用户占用；
    - 地址长度校验。
3. 实时反洗钱名单筛查，总开关控制。
4. 实时风控检查，按渠道开关控制。
5. 提交事后风控。
6. 公安联网核查，异步执行。
7. 账户认证通道。

### 4.3 核心处理
1. 打款认证。
2. 本行核心认证。
3. 二代认证。
4. 银联五要素认证。

### 4.4 处理影子三类户开户
1. 复用二类户开户信息及绑定卡。
2. 请求核心开通影子三类户。
3. 三类户开户成功。

### 4.5 返回开户结果
返回二类户 + 三类户开户结果。

## 5. 业务疑问
1. 为什么开了二类户还要开三类户？
2. 二类户、三类户分别用来做什么交易？

# 七、OCR 影像审核
## 1. 重点
业务。

## 2. 功能描述
OCR 影像审核主要关注：

1. 上传的证件影像是否正确。
2. OCR 识别出来的内容与客户填写的信息是否一致。

## 3. 代码清单
FM9401。

## 4. OCR 影像审核流程
### 4.1 前端
上传身份证影像。

### 4.2 E 账通
1. 判断 OCR 开关是否打开。
2. 若关闭：返回 OCR 审核通过。
3. 若打开：继续 OCR 审核流程。

### 4.3 OCR 审核流程
1. 根据影像编号查询影像图片。
2. OCR 识别影像内容，可按渠道配置 OCR 接口类型。
3. OCR 审核内容包括：
    - OCR 识别信息是否齐全，风险提示是否为“正常”；
    - 前端上送证件号码是否与 OCR 识别证件号码一致；
    - OCR 识别性别是否与身份证号码倒数第二位一致，男单女双；
    - 证件到期日是否到期，证件有效期是否满足规则；
    - OCR 识别证件号与 OCR 识别出的生日是否一致。
4. 判断 OCR 审核是否通过：
    - 不通过：报错；
    - 通过：继续判断身份证头像人脸识别是否打开。
5. 身份证头像人脸识别：
    - 若按渠道打开：调起人脸识别，返回成功结果；
    - 若未打开：直接返回成功结果。

## 5. OCR 接口类型
| OCR 接口 | 特点 |
| --- | --- |
| 头像服务端接口 | 无身份证风险识别，仅识别文字，识别率相对较低 |
| 实验室 / 学习型 OCR 接口 | 有身份证风险识别功能，识别率较高 |
| 百度 OCR 接口 | 有身份证风险识别功能，识别率最高 |


## 6. OCR 审核通过条件
需同时满足：

1. 所有信息识别完整，风险提示为“正常”。
2. 前端上送证件号码与 OCR 识别证件号码一致。
3. OCR 识别性别与证件号码倒数第二位一致，男单女双。
4. OCR 识别出生日期与身份证号出生日期一致。
5. OCR 识别证件到期日未过期，且满足有效期规则：
    - 16 周岁以下：有效期 5 年；
    - 16 至 25 周岁：有效期 10 年；
    - 26 至 45 周岁：有效期 20 年；
    - 46 周岁以上：长期。

## 7. 内管功能
| 功能路径 | 用途 |
| --- | --- |
| 账户管理 > 影像 > 影像信息查询 | 查询影像信息，一个电子账户通常有一条记录 |
| 账户管理 > 影像 > 后台 OCR 结果查询 | 查询 FM9401 OCR 审核对比结果 |
| 账户管理 > 影像 > 百度 OCR 识别报表 | 查询百度 OCR 调用流水 |
| 账户管理 > 影像 > 深度学习 OCR 识别报表 | 查询深度学习 OCR 调用流水 |
| 账户管理 > 影像 > 人脸识别报表 | 查询百度人脸比对识别结果 |


## 8. 补充说明
1. 客户上传影像后，调用开放平台接口。
2. 开放平台处理完后，给前端返回影像流水。
3. 前端再将影像流水、客户填写的身份证号等信息送 E 账通 FM9401 接口做 OCR 影像审核。
4. 人脸识别需要确认是否将人脸与身份证头像做对比。
5. 人脸影像是否与身份证影像一起上传，需要确认。
6. 不同年龄段证件有效期规则需要根据客户年龄判断。

## 9. 技术方案
1. 调用各个后端系统接口，完成相关操作。
2. 记录影像信息、OCR 流水。
3. 根据渠道配置做对应处理。

# 八、公安联网核查 / 公安认证
## 1. 重点
1. 业务。
2. 技术方案。

## 2. 功能描述
文件未展开具体内容。

## 3. 本地核查记录处理
根据证件号查询本地是否存在公安联网核查记录。

### 3.1 不存在核查记录
直接发起公安联网核查流程。  
说明：联网核查由天府人行通道处理，跳过本地公安通道，但对程序逻辑无影响。

### 3.2 存在核查成功记录
按以下规则判断：

1. 判断姓名是否一致：
    - 不一致：报错；
    - 一致：继续判断是否未满认证记录。
2. 判断是否未满认证记录：
    - 不满：重新做联网核查；
    - 满：判断是否超过 3 分钟。
3. 判断认证记录是否超过 3 分钟：
    - 超时：重新做联网核查；
    - 未超时：复用核查记录。

### 3.3 存在核查失败记录
按以下规则判断：

1. 判断证件号是否已开档：
    - 未开户：重新做联网核查；
    - 已开户：判断姓名是否一致。
2. 判断姓名是否一致：
    - 不一致：报错；
    - 一致：重新做联网核查。

## 4. 联网核查接口处理
开户联网核查使用后台系统接口 GMSF01。

| 核查结果 | 处理方式 |
| --- | --- |
| 成功 | 新增 / 更新本地联网核查记录，并继续开户 |
| 失败 | 新增 / 更新本地联网核查记录，并拒绝交易 |
| 异常 | 新增 / 更新本地联网核查记录，并继续开户，同时暂禁电子账户 |


## 5. 异常数据回查
针对联网核查异常数据，通过自动任务 freezeEaccountQuery 回查处理。

| 回查结果 | 处理方式 |
| --- | --- |
| 成功 | 解除电子账户暂禁 |
| 失败 | 保持暂禁，并自动销户 |
| 异常 | 继续回查 |


## 6. 公安联网核查技术方案
公安联网核查异步执行，因为公安联网核查不影响后续开户流程。后续流程走完之后，再回查公安联网核查结果。

处理规则：

1. 如果回查结果为“通过”：开通电子账户，账户状态正常。
2. 如果回查结果为“未处理完毕”：开通电子账户，账户状态为暂禁。
3. 如果回查结果为“失败”：不开户，返回开户失败。

# 九、银联认证
## 1. 业务理解

| 银联五要素 | 五要素包括证件号码、姓名、银行卡号、银行卡预留手机号、是否一类户；接口返回认证成功即视同四要素认证成功且为一类户；12 家联盟一般会配置该通道 |
| UPOP 签约 | 仅作为代收签约通道 |

# 十、建立客户档信息
## 1. 旧流程
1. 开始。
2. 查询 ECIF 客户信息。
3. 判断 ECIF 是否存在客户档：
    - 存在：更新 ECIF 客户信息；
    - 不存在：进入查询核心客户状态。
4. 查询核心客户状态。
5. 建立 ECIF 客户档，上送三证。
6. 更新 ECIF 客户信息，上送 9 要素。
7. 判断核心客户档状态：
    - 核心已建档：结束；
    - 核心未建档：新建核心客户档。
8. 结束。

## 2. 新流程
1. 开始。
2. 查询 ECIF 客户信息。
3. 判断 ECIF 是否存在客户档：
    - 存在：更新 ECIF 客户信息；
    - 不存在：建立 ECIF 客户档，三证 + 9 要素。
4. 查询核心客户状态。
5. 判断核心客户档状态：
    - 核心已建档：结束；
    - 核心未建档：新建核心客户档。
6. 结束。

## 3. 要素要求
| 户类 | 必填要素 |
| --- | --- |
| 二类户 | 九要素齐全 |
| 三类户 | 四要素齐全：证件类型、证件号码、姓名、手机号 |


## 4. 要素规则
| 要素 | 规则 |
| --- | --- |
| 证件类型 | 仅支持中国居民二代身份证，以前端上送为准 |
| 证件号码 | 仅支持 18 位身份证号，以前端上送为准 |
| 姓名 | 以前端上送为准 |
| 国籍 | 仅支持中国，E 账通默认送值，无需前端上送 |
| 性别 | 根据证件号码倒数第二位取值，男单女双 |
| 证件到期日 | 优先以本地后台 OCR 识别结果为准；无 OCR 值时以前端上送为准 |
| 职业 | 前端提供一级、二级职业供客户选择，接口仅上送第二级职业代码值 |

# 十一、影像审核：开户后异步执行
## 1. 定时任务
1. E 账通定时自动任务 sendShadowAuditingInfo 查询影像表。
2. 查询条件：
    - 影像状态为“待审核”或“可疑重审”；
    - 影像发送时间为空。
3. 符合条件时，推送影像给流程银行。
4. 若发送时间距离当前系统时间超过 20 天，会重新发送该笔影像审核任务。
5. 流程银行接收任务后进行人工审核。
6. 人工审核后台实时调用 E 账通 FM8305 接口返回影像审核结果。

## 2. 影像状态处理规则
| 影像状态 | 状态说明 | 是否发送短信 | 处理规则 |
| --- | --- | --- | --- |
| 00-未上传 | 指未上传影像；二类户控制交易，三类户不控制交易，包括充值、提现、放款、消费 | 不发送 | 无需处理 |
| 01-待审核 | 已上传影像，待人工审核；二三类户都不控制交易 | 不发送 | 推送影像审核任务给流程银行 |
| 02-审核通过 | 上传影像已审核通过；二三类户都不控制交易 | 发送审核通过短信 | 通过异步任务 ShadowunFreezeEacc 处理：解除 B014-影像异常灰名单；解冻开户后影像待审核且按配置冻结的电子账户；解除因“确认非本人”导致的暂禁电子账户 |
| 03-审核不通过 | 上传影像审核不通过；二三类户都控制交易 | 发送审核不通过短信，客户可通过短信 H5 短链接更新影像 | 按审核不通过原因处理 |
| 04-身份证已过期 | 因身份证已过期审核不通过；二三类户都控制交易 | 发送审核不通过短信，客户可通过短信 H5 短链接更新影像 | 同“审核不通过”流程 |
| 05-可疑重审 | 上一次影像审核不通过或身份证已过期，重新更新了影像；二三类户都控制交易 | 不发送 | 推送影像审核任务给流程银行 |


## 3. 审核不通过处理规则
| 不通过原因 | 处理规则 |
| --- | --- |
| 14-确认非本人 | 将证件号加入开户黑名单，不允许再开户；暂禁该证件号名下所有已开立电子账户，包括二类户、三类户 |

| 确认非本人后 30 天内未更新影像 | 通过自动任务 noYxEaccLogout 自动销户 |
| 01-18，不含 00、14、17 | 将电子账户加入核心 B014-影像异常灰名单 |
| 00、17 | 不做特殊处理 |
