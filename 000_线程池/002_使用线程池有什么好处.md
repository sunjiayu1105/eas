# 002_使用线程池有什么好处

以下内容按照当前项目 `AGENTS.md` 项目级规则中规定的技术栈版本为准，使用 Java 8。示例用于解释机制，不代表生产配置或测试结果。

## 1 问题

使用线程池有什么好处？

**复用线程，减少开销**

线程池通过复用工作线程，减少反复创建和销毁线程带来的 CPU、内存分配回收和启动时间开销。

**分离任务提交与线程管理**

业务代码主要负责提交任务，由线程池管理工作线程的创建、复用和回收，减少业务代码直接管理线程的工作。

**合理配置，控制并发**

合理配置线程数量，可以约束同时执行的任务数，避免创建过多线程造成资源竞争。控制效果取决于具体实现和配置，不能认为使用线程池就一定更快或资源占用更低。

## 3 详细方案

### 3.1 复用的收益与限制

大量短任务反复新建线程时，需要反复分配线程栈等资源、初始化线程，并在结束后清理。复用已有线程可以减少这些重复工作；有空闲线程时，也能减少等待新线程启动的时间。

减少分配和回收开销，不等于内存占用一定更低：保留的空闲线程仍会占用资源。线程复用也不能保证所有场景都更快；数据库已成为瓶颈时，增加工作线程可能只有更多等待。

### 3.2 任务提交与线程管理分离

任务描述要做什么，线程负责执行任务。使用线程池后，业务代码提交任务，由线程池安排工作线程执行；不必为每个任务自行创建、启动和回收线程。这里说明的是职责分离，不依赖某个实现类特有的关闭或监控方法。

### 3.3 示例：两个线程依次执行四个任务

假设采用固定 2 个工作线程、能够容纳 2 个等待任务的先进先出队列；仅由工作线程执行任务。以下是机制示例，线程池保持运行，任务正常完成。

1. 提交任务 A、B，分别由工作线程 T1、T2 执行。

2. A、B 尚未结束时提交 C、D，C、D 等待执行。

3. 假设 A 先完成，T1 取出 C 并执行，不必为 C 创建新线程。

4. 假设 C 仍在执行时 B 完成，T2 再取出 D 并执行，不必为 D 创建新线程。

四个任务由两个工作线程承接，体现了线程复用和并发控制。业务代码负责提交任务，工作线程的安排由线程池负责。

### 3.4 并发控制依赖实现和配置

线程池提供集中管理执行资源的机制，但不能只凭“使用了线程池”就认定资源有上限。需要根据具体实现确定线程数量的约束和待处理任务的承载方式；如果线程或待处理任务持续增长，仍可能占用过多资源。线程池也不替代业务进度保存、失败处理和数据一致性机制。
